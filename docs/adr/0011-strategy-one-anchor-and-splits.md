# ADR-0011: 전략 1호 — 급등 앵커 피보나치와 분할 매수/매도

- **상태:** 수락 (계산 코어 / 체결 시뮬레이션·UI 미착수)
- **날짜:** 2026-08-05
- **관련:** BORB-50·51, ADR-0009(전략은 데이터), ADR-0006(수정주가), CLAUDE.md(look-ahead 금지)
- **대체:** ADR-0009 의 `fib_retrace` 앵커 정의(베이스 탐지)를 이 문서가 대신한다.

## 맥락 (Context)

오너가 기존 구현을 거부했다. 화면에 `탐색 구간 / 베이스 최소 길이 / 베이스 최대 변동폭`
세 칸이 떠 있는 걸 보고 — "베이스 최소 길이를 왜 입력으로 넣어. 최대 변동폭도."

기존 앵커는 "평평한 구간을 찾아 그 최저 종가"였다. 오너 전략은 그게 아니다.

> 급등한 것의 **시가**를 피보나치 시작으로, **52주 신고가**를 끝으로 잡는다. 되돌림 레벨
> 근처의 라운드 피겨에 1·2·3차 분할 매수. 매도도 반등 몇 % 의 라운드 피겨에 1·2차.
> 이게 아닐 때도 있으니 각각 커스텀으로 추가·해제하면서 차트로 본다.

**매매 성격이 앞서 오해됐던 것도 바로잡는다.** 기준봉 당일에 사는 게 아니다. 급등이
**이미 끝난** 종목을 찾아, 나중에 미리 걸어둔 지정가로 눌림·낙주를 받는다.
그래서 "신호일 종가에 샀다"는 look-ahead 논쟁은 이 전략에 해당하지 않는다 — 신호는 과거에
있고 체결은 사전에 정한 가격에서 일어난다.

## 결정 (Decision)

계산 코어를 세 모듈로 나눈다. 전부 결정론이고 전략 숫자는 하나도 안 박혀 있다(ADR-0009).

### 1. `surge.py` — 급등 파동과 앵커

- **상승률은 시작일 Open → 창 안 최고 High** 로 잰다. 앵커 시작점이 Open 인데 상승률을
  종가로 재면 같은 파동을 두 자로 재는 셈이라 경계에서 판정과 앵커가 어긋난다.
  끝을 High 로 잡은 건 급등이 장중에 완성되는 일이 흔하고(상한가·장대양봉) 되돌림은 그
  고점에서 재야 하기 때문. 52주 신고가도 관행이 장중 고가라 자가 통일된다.
  대가: **윗꼬리 한 방으로도 급등 판정이 난다.** 꼬리를 걸러내려면 호출부가
  `min_gain_pct` 를 올린다 — 모듈에 "꼬리 몇 %" 같은 숫자를 박지 않았다.
- **동률 규칙이 방향에 따라 다르다.** 고가 동률(급등 완성일·52주 신고가)은 **가장 이른 날**
  (파동은 고점을 처음 찍은 날 완성된다). 시작일 동률은 **가장 늦은 날** — 평평한 구간에서
  이른 날을 고르면 베이스 한복판이 급등 시작일로 찍힌다. 시가가 같아 앵커 **가격**은
  어느 쪽이든 같고 날짜 라벨만 정확해진다.
- **52주 창은 캘린더로 자른다**(`weeks × 7`일). "약 250거래일" 근사를 쓰면 휴장일 수가
  해마다 달라 실제 기간이 51~54주로 흔들린다. 52주는 캘린더 정의다.
- **끝점을 52주 창으로 다시 자르지 않는다.** 자르면 급등이 52주보다 오래된 데이터에 있을 때
  "급등 이후" ∩ "52주 창"이 비어 앵커가 뒤집힌다(끝가 < 시작가). 끝점은 "급등 시작일 이후
  최고 High"로 정의하고, **실제 52주 신고가와 같은지는 `is_52w_high` 플래그로 넘긴다** —
  버릴지 말지는 호출부가 정한다.
- **`as_of` 를 주면 그 시점까지만 본다.** 안 주면 데이터 끝까지 본다 — 과거 시점
  시뮬레이션에서는 반드시 준다. 세 함수 독스트링에 각각 경고를 남겼다.
- **갭 상승 시작 → 앵커는 갭 전날 시가.** (오너 확정 2026-08-05) 갭 자체도 상승의
  일부다 — "급등이 시작된 날"은 갭이 뜬 날이 아니라 그 상승이 출발한 전날이다.
  "창 안 최저 시가" 규칙이 이미 이렇게 동작하므로 코드 변경 없음. 파동폭이 커져
  매수가가 낮게 잡히는 보수적 방향과도 일치한다.

### 2. `entry_levels.py` — 분할 매수/매도 레벨

- `tick_size.py` 를 재사용한다. 같은 계산을 다시 만들지 않는다.
- **차수는 체결이 닿는 순서다.** 매수는 가격 높은 쪽이 1차, 매도는 낮은 쪽이 1차.
  어긋나게 매기면 "1차만 체결됐다"가 뜻을 잃는다.
- **매수 차수는 반드시 가격 내림차순이다.** 라운드 피겨 후보는 레벨보다 위에도 있고
  굵은 것 우선 규칙 때문에 자주 뽑힌다 — 상한(ceiling)을 안 걸면 2차가 1차보다 비싸진다.
  (실측: low 50,000 / high 100,000, 허용폭 1.2% 에서 1차 80,000 · 2차 81,000.)
- **폴백 반올림은 체결이 덜 되는 쪽으로.** 매수는 내림, 매도는 올림. 백테스트가 낙관 쪽으로
  기울지 않게 한다.
- `sell_levels` 는 평단 이하 후보를 버린다. 반등 매도 자리에 손절가가 끼는 걸 막는다.

### 3. `avwap.py` — 앵커 VWAP (지지·저항)

- **`Amount / Volume` 을 쓴다.** 교과서 일봉 VWAP 은 `(H+L+C)/3` 로 근사하는데, marcap 에는
  거래대금이 있어 그날 실제 평균 체결단가를 그대로 얻는다. 근사가 아니라 정의 그대로다.
- back-adjust 와 자동으로 정합한다 — OHLC 는 ×f, Volume 은 ÷f, Amount 는 불변이라
  `Amount/(Volume/f) = (Amount/Volume)×f`. 보정된 Close 와 같은 축에 올라탄다.
- 거래정지일(Volume==0)은 가중치 0 으로 뺀다. 체결이 없던 날은 평균에 넣을 것이 없다.
- **하한 밴드에 0 바닥.** `mean − mσ` 는 변동계수가 1/m 을 넘으면 음수가 된다 — 급등주에서
  실제로 일어난다(1,000원 → 8,000원이면 −1σ 도 음수). 음수는 NaN 으로 막는다.
  0 으로 깔지 않은 이유: "0원에 사겠다"가 유효한 주문처럼 보여서 더 위험하다.
- **단가 출처(`source`)를 호출자가 못박을 수 있다.** 자동 판정은 프레임 전체를 훑으므로
  확장창으로 과거를 재현하면 미래 행의 유무가 과거 값을 바꾼다. 값 자체(cumsum)는 인과적인데
  **정의 선택이 미래를 봤다.** 백테스트 호출부는 `source` 를 명시한다.

## 결과 (Consequences)

- ② 매매전략 화면에서 베이스 관련 입력 세 칸이 사라지고, 급등 판정(기간·상승률)과
  분할 차수(비율·비중·허용폭)가 들어간다.
- 목표가는 **사용자가 적는 값이 아니라 기법이 계산하는 값**이 된다(ADR-0009 개정 3).
  차수마다 자동 계산값을 보여주고, 마음에 안 들 때만 덮어쓴다.
- 피보나치와 AVWAP 은 **서로 독립적인 근거**다. 하나는 파동 양 끝의 기하학, 하나는 실제
  체결. 겹치는 지점이 의미가 있고, 같은 정보를 두 번 세는 게 아니다.

## 검증 (Verification)

계산 코어를 만든 뒤 **look-ahead / 결정론 / ADR-0009 세 렌즈로 적대적 검증**을 돌렸다
(모듈 3개 × 렌즈 3개 = 9회 독립 검증). 차단급 4건이 나왔고 전부 고쳤다:

| 결함 | 증상 | 조치 |
|---|---|---|
| 매수 차수 역전 | 2차가 1차보다 비쌈 | 상한(ceiling) 도입 |
| AVWAP 하한 음수 | 급등주에서 −580원 | 음수 → NaN |
| 단가 출처가 미래 의존 | 뒤 행 유무로 과거 값 변경 | `source` 명시 가능 |
| 52주 창 미전달 | `weeks` 를 바꿔도 판정은 52주 고정 | 인자 전달 |

`tests/test_strategy_core_regressions.py` 가 이 넷을 고정한다. 전부 "예외도 NaN 도 없이
조용히 틀리는" 종류라 원래 모듈 테스트와 따로 모아 뒀다.

### 4. 손절 + 시뮬레이션 API (2026-08-05 추가, 오너 확정)

- **손절도 전략 데이터다.** 두 방식: ① 평단 대비 −X% ② **지지저항 기준 ±N호가**
  (기준선 = 앵커 VWAP / 급등 시작가 / 직접 가격, 오프셋 = `tick_size.shift_ticks` —
  구간 경계를 한 칸씩 넘는다. 50,000 의 한 칸 아래 = 49,950).
- `POST /api/simulate` — 계산 코어의 첫 노출. 앵커 → 분할 목표가 → 파동 고점 이후
  Low/High 스캔으로 체결 마커 → 손절 발동 시 이후 체결 취소(당일 겹침은 보수 방향:
  매수 유지·매도 취소) → 체결 내역(차수별 수량·평단·실현/평가손익, **비용 미포함**).
  화면은 전략 화면 ③ 시뮬레이션 탭 — 종목 차트 오버레이 ❌ (오너 지시).
- 조건검색·시뮬레이션 기본 기준일 = **마지막 완결 거래일(전날)**. 장중 데이터로 조건을
  평가하지 않는다. 실시간 시세(네이버 폴링)는 관심종목·종목상세 등 **표시에만** 쓴다.

## 미해결 (Open questions)

1. **`is_52w_high=False` 인 종목을 거를 것인가.** 지금은 플래그만 넘기고 호출부에 맡긴다.
2. **매도 기준점.** 1차만 체결된 평단과 3차까지 채운 평단이 다르다. 화면에서 고르게
   두었지만(`avg_entry`/`lowest_fill`/`anchor_high`) 어느 쪽이 기본인지 미정.
3. **되돌림 비율을 0~1 로 제한했다.** 피보나치 확장(1.272·1.618)을 낙주 하단 목표로 쓰려면
   별도 함수가 필요하다.
4. 라운드 피겨 후보 우선순위("굵은 것 먼저")가 코드 상수다. "레벨에 가장 가까운 것"과
   결과가 1% 이상 갈리는데 오너가 못 바꾼다 — 파라미터 승격 검토.
5. ETF/ETN 호가단위(`kind`)가 기본값 `"stock"` 이고 UI 에 지정 경로가 없다.
