# ADR-0018: 주문 창구 = 나무증권(NH PLUG), KIS 는 데이터용으로 병행

- **상태:** 수락 (조건부 — 모의투자 주문 왕복 검증 1건 남음, 아래 미해결 1번)
  · **주·월봉 정본 결정은 2026-08-29 개정으로 뒤집혔다** (문서 끝)
- **날짜:** 2026-08-15
- **관련:** ADR-0010(KIS 어댑터), ADR-0012(수급 소스), BORB-78, BORB-79
- **대체:** CLAUDE.md 의 "주문 창구 = KIS" 결정을 뒤집는다. ADR-0010 은 조회 전용으로 존속.

## 맥락 (Context)

NH투자증권이 2026-08-10 오픈API **PLUG**(나무 플러그 / N2 플러그)를 정식 출시했다.
오너 계좌가 나무증권이고, 수수료가 국내주식 0.01%(신규 24개월 무료)로 KIS 온라인
수수료(약 0.014%)보다 싸다. 오너 지시(2026-08-15): "KIS 에서 나무로 바꾸고, 둘 다
쓰는 구성도 검토하라."

출시 5일차 서비스라 추측 대신 실측으로 갈랐다. 앱키를 발급받아 운영 서버를 직접
호출한 결과(`scripts/namuh_probe.py`):

| 실측 항목 | 결과 |
|---|---|
| 일봉 | 넘김 조회로 1990년~ (한 호출 최대 5,000건) |
| 주봉/월봉 | 1990년~ / 1986년~ |
| 분봉 | 1~240분 전부. 굵을수록 깊다(1분 약 6주, 240분 약 6년) |
| 수급(일별) | 최대 999건 = 2022-07~. **날짜 지정 불가 — 더 과거는 못 받는다** |
| 호출 한도 | 실측 초당 약 7건 (문서 미기재) |
| 모의투자 | 있음(moapi, 계좌구분 03). 단 토큰은 운영 서버 전용, **영업일에만 주문 접수** |
| 계좌·잔고·체결내역 | 전부 조회됨 (`/n2/acctinfo` 로 계좌 자동 발견 — 계좌번호 설정 불요) |
| 수정주가 | 봉 데이터는 수정주가 (2018 삼성전자 분할 구간으로 확인) |
| 명세 함정 | openapi.json 의 `Output_0` 위치가 실응답과 다름 — **봉 배열은 `Output_1`** |

KIS 와의 차이 중 결정에 영향을 준 것:

- KIS 는 수급 이력이 1994-11 까지 나오고(추가 실측), 나무는 2022-07 이 바닥이다.
- KIS 모의투자는 전용 앱키로 완전 분리되지만, 나무는 운영 키 하나로 모의를 호출한다
  (주소 실수 = 실계좌 위험 → SDK 의 호스트 검증 + 스크립트에서 moapi 강제로 방어).
- 나무는 공식 파이썬 SDK(`nhplug`)·공식 MCP·llms.txt 를 제공한다. KIS 는 샘플코드 중심.
- 나무의 API 폭은 좁다(국내주식 31개). 조건검색·순위·업종 API 가 없다 —
  우리는 조건검색을 자체 계산(BORB-41)으로 가고 있어 영향 없음.

## 결정 (Decision)

**3층 구조로 역할을 나눈다. 어느 한쪽 전면 교체가 아니다.**

| 층 | 담당 | 근거 |
|---|---|---|
| **매매(주문·정정·취소·체결내역)** | **나무 PLUG** | 오너 계좌·수수료·공식 SDK |
| **앞으로의 시세 수집** (일·주·월·분봉 증분) | **나무 PLUG** | 한 호출 5,000건 — KIS 의 50배 |
| 과거 수급 백필 (1995~) | KIS (조회 전용, ADR-0012) | 나무는 2022 이전을 못 준다 |
| 백테스트 일봉 정본 | marcap (ADR-0002) | 상폐 종목 포함은 여기뿐 |

따라 나오는 결정:

1. ~~**주·월봉 차트 정본 = 나무 수집본.**~~ → **뒤집혔다. 아래 「개정 2026-08-29」를 본다.**
   지금은 우리 일봉으로 만든 값이 정본이다. 화면 쪽 합성(`api.main.period_candles`)은
   그대로다.
2. **봉 전량 수집**: 전 종목 × 일/주/월 + 분봉 9종을 `data/derived/namuh_bars/` 에
   parquet 으로 (`scripts/collect_namuh_bars.py`, 체크포인트 이어받기).
3. **수집 데이터는 저장소 밖.** KRX 원천 시세의 재배포 금지 관행 + 용량(수 GB) 때문에
   GitHub 업로드 금지, 로컬 `data/`(gitignore) 유지. 오너 확인 2026-08-15.
4. KIS 실전 키·어댑터(ADR-0010)는 **조회 전용으로 유지**한다. 폐기하지 않는다.
5. 실계좌 주문 실행은 사람이 스크립트로만(`scripts/namuh_buy_one.py`, 2중 확인).
   자동매매 경로의 주문 어댑터는 모의(moapi) 검증 후 별도 작업(BORB-78).

## 결과 (Consequences)

- `.env` 에 `NHPLUG_APP_KEY/SECRET/BASE_URL` 추가. 계좌번호는 넣지 않는다(API 로 발견).
- 의존성 `nhplug`(공식 SDK, MIT) 추가 — `pyproject.toml [namuh]`.
- 신생 서비스 리스크는 남는다: 문서에 한도 미기재(실측 의존), 장애 이력 없음,
  명세·실응답 불일치. 어댑터는 명세를 믿지 말고 실응답 기준으로 짠다.
- 모의 격리가 약한 만큼, 주문 코드는 **모의 서버 강제 + 계좌구분 검증**을 코드로 넣는다
  (`scripts/namuh_mock_order.py` 방식).
- 개발 규칙은 공식 템플릿(nhplug-sdk `templates/CLAUDE.md`)을 어댑터 작업 때
  프로젝트 참조 문서로 들여온다.

## 미해결 (Open questions)

1. **모의투자 주문 왕복 검증** — 2026-08-15 는 휴장일이라 "모의투자 영업일이 아닙니다"
   (14100). 다음 거래일 장중에 `scripts/namuh_mock_order.py` 실행. 통과가 이 ADR 의
   채택 조건이다. 실패하면 주문 창구 결정만 되돌리고 데이터 수집 결정은 유지한다.
2. Layer 4 주문 어댑터(나무) 구현과 KIS 어댑터와의 인터페이스 통일.
3. 공식 MCP(nhplug-mcp) 조회 전용 연결 — 연결 시 주문 도구를 settings deny 에 등록
   (CLAUDE.md 의 KIS MCP 규칙과 같은 방식).
4. PROJECT_GUIDELINES(§ 단계 5 "KIS 무료 모의투자" 등)의 본문 반영 — 다음 판 개정 때.
   그 전까지는 이 ADR 이 정본이다.

## 개정 2026-08-18 — 일봉 증분은 KIS 멀티시세, 장중은 차트 연 종목만 나무 웹소켓

**계기:** 저녁 갱신이 새 거래일마다 나무 봉 16,530콜(약 50분). 나무 `period` 는 서버 한도가
초당 5건(실측: 5.6건에서 429, 10건에서 절반 거절)이라 나무만으론 못 줄인다.

**결정 (오너 2026-08-18):**
1. **오늘 일봉만 KIS 관심종목 멀티시세(`FHKST11300006`, 30종목/콜, `J`/`UN`/`NX`)** 로 붙인다.
   나무 일봉과 240봉 대조: 가격·거래량 240/240 일치, 통합 거래대금만 0.003% 차(오너 수용).
   20:05 이후·오늘이 거래일일 때만(그 전엔 미완성) — 아니면 나무 경로. 응답 전일종가 ≠ 우리
   마지막 종가면 액면분할·병합으로 보고 그 종목만 나무에서 전체 재수집(전엔 이 구멍이 있었다).
   표본 20종목은 매번 나무와 대조해 요약에 남긴다.
2. **주·월봉도 매일, KIS 기간별시세(`FHKST03010100` W/M, 5줄기)** — "직전 기준으로 업데이트".
   일봉으로 합성해 저장하는 안은 기각(위험).
   > ⚠️ **이 줄은 2026-08-29 개정으로 뒤집혔다**(문서 끝). 지금은 일봉으로 만들어 저장하고
   > KIS 로 매일 받지 않는다. 아래 ①②③ 의 차이 처리는 그대로 쓴다.

   나무는 서버 한도 초당 5건이라 34분, KIS 는 약 12분
   (실측 120종목 304콜 22초). 나무와의 차이는 셋인데 전부 다뤘다: ① 수정주가 반올림 ±1원·거래량
   몇 주(이력에 액면변경이 있는 종목만) — 오너 수용. ② 주봉 날짜 KIS=월요일 → 우리 일봉 파일의
   그 주 마지막 거래일로 바꿔 나무와 같게. ③ **연말 주(12/31·1/1 이 같은 주)는 KIS 로 안 받고
   나무에 맡긴다** — 나무는 그 주를 둘로 쪼개고 KIS 는 안 쪼갠다(1년 1회, 그 주만 나무 17분).
   같은 주·달의 옛 진행 봉은 지우고 새 봉으로 바꾼다(수요일 봉·목요일 봉이 둘 남지 않게).
   주의: 통합 거래대금은 KIS 와 나무가 최대 1.2% 다른 봉이 있었다(가격·거래량은 같다) —
   두 회사가 통합 대금을 다르게 계산한다. 일봉 멀티시세의 0.003% 와 같은 성격.
3. **장중엔 전 종목 갱신하지 않는다.** 어제까지가 정본. 차트를 연 종목만 나무 실시간
   체결(WebSocket `oc`/`mc`/`nc`, 조회 전용)로 오늘 봉을 진행형으로 그린다 — 파일엔 안 쓴다.
   (`src/layer1_data/namuh_live.py`, `/api/live/bar`, `web/src/liveBar.ts`)
   실측: 접속 경로는 `wss://api.nhplug.com:7070/websocket` — SDK `ws_url()` 값(경로 없음)으로는
   악수가 안 끝난다. 15:20~15:30 동시호가·NXT 휴지 시간엔 체결 푸시가 없는 게 정상.
4. KIS 수급·거래원 줄기 3 → 5 (초당 10건, 한도 20). 거절은 재시도가 받는다.
5. 마지막 거래일 관문은 나무 기준 종목이 먼저 — KRX Open API 는 다음날 08:00 갱신이라
   저녁엔 어제가 나온다.

**결과:** 새 거래일 갱신 ≈ 일봉 1분 + 주·월봉 약 12분 + KIS 수급·거래원 약 6분 → **약 20분**(전 80분). 이후 실측으로 갱신.

## 개정 2026-08-29 — 주·월봉 정본을 "나무 수집본"에서 "우리 일봉으로 만든 값"으로 바꾼다

**이 개정은 위 「결정」의 1번과 「개정 2026-08-18」의 2번을 뒤집는다.** 자세한 근거와
실측은 [ADR-0021](0021-period-bars-from-daily.md).

### 왜 뒤집나

2026-08-18 에는 "일봉으로 합성해 저장하는 안은 기각(위험)"이라고 적었다. 그때는 나무
수집본이 맞다고 보고, 합성값이 그것과 어긋나는 걸 위험으로 봤다. **전 종목을 대조해 보니
반대였다.**

| 재 본 것 | 결과 |
|---|---|
| 전 종목 4,310개·63만 봉 대조 | **1,339종목(31.1%)이 어긋남** |
| 어긋난 종목을 나무에서 **전량 재수집** | 값이 그대로 — 나무 서버가 원래 그 값을 준다 |
| 어긋난 것을 KIS 로 심판 | **14건 전부 "일봉이 맞고 나무 주봉이 틀리다"** (나무=KIS 0건) |

예: 한화(000880) 2026년 8월 첫째 주 — 저장된 주봉만 83,800 원이고 나무에 다시 물어도,
KIS 도, 우리 일봉으로 만들어도 100,600 원이다. **주·월봉만 옛 수정주가로 굳어 있었다.**
335870 은 나무 주봉만 정확히 5배 — 액면분할이 주봉에 안 먹은 것이다.

일봉은 액면 변경이 잡히면 그 종목을 통째로 다시 받아 갱신하는데, 주·월봉은 그 길이
없었다. 그래서 시간이 갈수록 벌어진다.

### 무엇으로 바꾸나

| | 전 (2026-08-18) | 후 (2026-08-29) |
|---|---|---|
| 주·월봉을 누가 만드나 | 나무 수집본이 정본, 매일 KIS 로 갱신 | **우리 일봉으로 만든다** |
| 증권사 호출 | 매 회차 5,140콜 · 358초 | **0콜** |
| 어긋난 과거 봉 | 손대지 않음 | **일봉으로 만든 값으로 덮는다** |
| 나무·KIS 의 자리 | 정본 | 저장본이 아예 없는 종목을 처음 받을 때만 |

호출이 전체의 64% 를 차지하던 단계가 통째로 사라진다. 대신 매 회차 전 종목을 일봉과
맞춰 보고, 어긋나면 그 자리에서 고친다.

### 안 바뀌는 것

- 봉 파일 형식·폴더 구조는 그대로다. 나무가 주던 14개 열을 그대로 쓴다.
- 연말·연초에 걸친 주는 여전히 **나무 규칙(쪼개기)** 을 따른다. KIS·화면 코드와 규칙이
  다를 뿐 어느 쪽이 틀린 게 아니라, 대조에서 뺀다.
- 일봉·분봉·수급·주문 창구 결정은 하나도 안 건드린다.
- 화면 쪽 합성(`api.main.period_candles`)도 그대로다 — 거기는 그리기용 표를 다루고
  여기는 수집본 파일을 다룬다. 묶는 규칙은 같다.

### 되돌리려면

예전 경로(`update_period_bars_kis`)를 지우지 않고 남겨 뒀다. 한 줄을 되돌리면 다시
KIS 로 받는다. 전 종목을 나무에서 다시 받아도 62분, KIS 로는 8.6분이다.
