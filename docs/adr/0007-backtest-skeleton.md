# ADR-0007: 백테스트 엔진 골격 (얇은 자체 엔진)

- **상태:** 수락 (골격만 / 체결 시점·포지션 크기 미확정)
- **날짜:** 2026-07-24
- **관련:** BORB-31, CLAUDE.md(자체 얇게), §4.1(3분할), ADR-0004(비용), ADR-0006(수정주가), BORB-32(거래정지)

## 맥락 (Context)

Layer 1 데이터 검증이 끝났고(BORB-32 포함), 다음은 백테스트 골격이다.
CLAUDE.md 확정: **메인 엔진 = 자체 구현, 얇게.** vectorbt/backtesting.py 는 P&L 대조 oracle 로만.

## 결정 (Decision)

`src/layer4_execution/backtest.py` — 한 종목 일봉 단위의 결정론적 엔진.

1. **체결 규칙**: 신호일(t)의 **다음 날(t+1) 이후 첫 거래 가능일 시가** 체결.
   "신호 계산 시점 < 체결 시점" 불변식이 엔진 구조로 강제된다.
   ※ t+1 시가는 **placeholder** — ADR-0001 폐기로 진입 방식은 전략 확정 후 새 ADR 로 정한다.
2. **거래정지**: 체결일 `Amount==0` 이면 다음 거래 가능일로 미룬다(진입·청산 동일).
   근거: BORB-32 점검 — `Amount==0 ⇔ Volume==0`, 2017+ 구간 4.24%.
3. **비용**: ADR-0004 `CostModel` 왕복 정액률을 거래마다 차감. 기본 수준 2(0.5%).
4. **3분할 가드**: §4.1 구간(Train 2020~2023 / Validate 2024 / Test 2025)을 상수로 박고,
   Test 는 `i_know_test_is_once=True` 명시 없이 못 자른다.
5. **신뢰 플래그**: 요약에 `n_trades` 와 `reliable(N≥30)` 을 함께 낸다.
6. **수정주가 정본 이동**: ADR-0006 보정 로직을 `api/main.py` → `src/layer1_data/adjust.py` 로
   이관. 차트와 엔진이 같은 정본을 쓴다.
7. **전량 진입/전량 청산** 단순 모델. 포지션 크기·분할 매매·복수 종목 포트폴리오는
   전략 확정 후 확장한다.

## 결과 (Consequences)

- 전략(layer3)은 "0/1 목표 포지션 열"만 만들면 되고, 체결·정지·비용은 엔진이 책임진다.
- 엔진은 position[t] 가 t일까지의 데이터만 썼는지 **검증할 수 없다** — 그건 코드 리뷰
  (backtest-validator)와 전략 코드 규율의 몫이다.
- 미청산 포지션은 거래로 세지 않는다(보수적). 장기 보유 전략 평가 시 왜곡 가능 — 확장 시 재검토.

## 미해결 (Open questions)

1. 체결 시점 확정(전략 확정 후 새 ADR). 슬리피지 곡선(ADR-0004 미해결)과 함께.
2. 포트폴리오 수준(복수 종목·자금 배분·동시 신호 우선순위).
3. oracle 대조(vectorbt/backtesting.py)로 P&L 검산 — 전략이 하나 생기면 수행.
