# ADR-0014: 목표가 = 지지/저항 — 라운드 피겨·앵커 VWAP 폐기, 존(채널) 표준 채택

- **상태:** 수락 + **개정 2 적용** (§1 자체 군집식 → TradingView Support Resistance Channels 포팅) + **5차 개정(2026-08-10): 매도는 지지/저항에 안 붙인다 — 맨 아래 절**
- **날짜:** 2026-08-06 (개정 2 같은 날)
- **관련:** ADR-0013(상승장 사이클), ADR-0009(전략은 데이터)
- **대체:** ADR-0011 §2(라운드 피겨 목표가)·§3(앵커 VWAP)를 이 문서가 대신한다.

## 맥락 (Context)

오너 확정(2026-08-06): "피보나치에서 근접 판정이라는 입력 자체를 없애고, **지지저항 기준으로
피보나치 각 단계에 가까운 지지/저항선에 ±호가로** 매수 매도가 되어야 하는 거야."
블로그·교과서에서 손으로 긋는 그 지지선/저항선 — 스윙 저점·고점의 수평선이다.

앵커 VWAP 도 같이 빠진다("지지저항 그게 아닌 거 같은데"). 사이클 저점(수년 전 바닥)
앵커에서는 26년치 평균(실측 삼성전자 33,627원 vs 현재가 248,000원)이 되어 지지선 구실을
못 한다.

## 결정 (Decision)

### 1. `support_resistance.find_levels` — 프랙탈 피벗 + 군집 (표준 오픈소스 기법)

- **피벗**: High 가 좌우 `span` 봉 포함 창에서 최고면 저항, Low 가 최저면 지지.
  동률은 창 안 최초 발생만(결정론).
- **우측 span 봉이 있어야 확정** — 기준일 시점에 알 수 없던 선은 만들어지지 않는다.
  look-ahead 가 구조적으로 차단된다(오너 요구: 기준일 왼쪽만).
- **군집화**: 피벗 가격 오름차순 탐욕 병합(`cluster_pct` % 안 = 같은 선). 선 가격 =
  구성 피벗 평균, `touches` = 피벗 수(여러 번 확인된 선일수록 크다).
- `span`·`cluster_pct` 기본값 없음(ADR-0009). UI 예시 10일·1%.

### 2. `entry_levels.buy_targets_sr / sell_targets_sr`

- 매수 = 각 되돌림 레벨에서 **가장 가까운 선** ± 매수 호가 오프셋. 호가 내림·동거리면
  낮은 선(보수), 차수 가격 내림차순 강제, 신고가 이상 선 제외(추격 매수 방지).
- 매도 = 각 반등 목표가(기준가×(1+반등률))에서 가장 가까운 **기준가 위** 선 ± 매도
  호가 오프셋. 호가 올림·동거리면 높은 선(보수), 오름차순 강제.
- 후보 부족은 ValueError — 조용히 차수를 지우면 오너가 건 분할이 사라진다.

### 3. 화면

- 근접 판정(near)·라운드 허용폭 입력 삭제. 호가 오프셋(매수/매도) 입력 추가(0 = 선 그대로).
- 파동·지지저항 파라미터의 정본 = ② 진입 기법 `fib_retrace`(`drop_pct`·`sr_span`·
  `sr_cluster_pct`). **③ 시뮬레이션은 실행만** — 전략 선택 + 기준일 + 요약 + 체결 내역 +
  차트(분할 카드 삭제, 오너 지시).
- 차트에 지지/저항선(kind `sr`, 회색 점선, "지지저항 N회 가격" 라벨) — 필터 칩으로 on/off.
- 손절 기준선 = 사이클 저점 | 직접 가격 (avwap·anchor_start 옛 저장분은 사이클 저점 이관).

### 4. 같은 날 추가 (오너 지적)

- **화면 용어는 쉬운 말** — `sr_span` = "고점·저점 기준"(좌우 N일보다 높은 고점/낮은 저점을
  선으로), `sr_cluster_pct` = "같은 선 폭"(가격 차이가 이 % 안이면 한 선). "피벗·군집"
  같은 용어 금지.
- **목표가를 못 걸어도 전체를 실패시키지 않는다** — 200 + `warnings` 로 이유를 알리고,
  그릴 수 있는 것(사이클·피보·지지저항·반대쪽 목표가)은 전부 그린다. "오류만 띄우면
  뭘 고쳐야 할지 모른다."
- **성능**: 시뮬 이력 로드가 연 파케이 32개 조립(6.5초)이었다 — 사전 계산본
  (`data/derived/adjusted`, build_adjusted.py) + 빌드 이후 꼬리 이어붙이기로 **0.38초**.
  이어붙인 전체에 보정을 한 번 더 태워도 이미 보정된 구간은 재감지되지 않는다(분할 감지 =
  주식수 급변 **그리고** 가격 역방향 점프, 둘 다 필요). 느린 길과 7,877행 OHLC 완전 일치
  확인. 계산 자체(사이클+지지저항 217선)는 28ms — 병목은 처음부터 데이터 로딩이었다.

### 5. 앵커 VWAP 폐기

시뮬 곡선·손절 기준·요약 표기에서 제거. `avwap.py` 모듈·테스트는 범용 유틸로 잔존
(백테스트 지표 후보) — 삭제는 오너 확인 후.

## 결과 (Consequences)

- 목표가가 임의의 라운드 숫자가 아니라 **차트가 실제로 여러 번 확인한 가격대**에 걸린다.
- 실측(삼성전자, 기준일 2026-08-06, -50%·피벗 10일·군집 1%): 선 217개,
  매수 223,000/209,000/167,100 — 전부 실제 지지선. 화면에 매도 기준가 병기.
- 지지/저항 파라미터 2개가 새 전략 자유도다 — 값은 백테스트(ADR-0007)로 검증한다.

## 개정 2 (2026-08-06) — 자체 군집식 폐기, TradingView "Support Resistance Channels" 포팅

오너 지시: "지지저항을 왜 그렇게 계산해? 같은 선 폭도. **임의로 계산식 만들지 말고
인터넷에서 찾아**" / "니가 하는 모든 개발이 이미 만들어져 있다는 사실을 알아두라고."

조사(2026-08-06, 출처는 코드 docstring에도 기록):

- 피벗 탐지(좌우 N일 스윙 고점·저점)는 이미 업계 표준과 동일했다 — TradingView
  `ta.pivothigh/pivotlow`, Bill Williams Fractals(MT5), smart-money-concepts(★1.9k).
- **비표준이던 것**: ① 군집 허용폭이 고정 %(저가주·고가주에 같은 % — 근거 없음),
  ② 평균낸 단일선(통용 관행은 상단·하단 있는 **존**), ③ 강도 개념 부재.

**채택**: 트레이딩뷰에서 가장 널리 쓰이는 자동 지지/저항 오픈소스 지표
LonesomeTheBlue **"Support Resistance Channels"** (MPL-2.0) 를 그대로 포팅.
<https://www.tradingview.com/script/Ej53t8Wv-Support-Resistance-Channels/>

- 존 최대 폭 = **최근 300봉 (최고가−최저가) × width%** — 종목 가격대에 자동 적응.
- 강도 = 존 안 피벗 1개당 20점 + 존에 닿은 봉(High/Low) 1개당 1점.
  `min_strength` 미달 존 폐기, 겹침 제거 후 **강도순 최대 `max_channels` 개**.
- 파라미터: `sr_prd`(피벗 기준)·`sr_channel_width_pct`·`sr_loopback`·`sr_min_strength`·
  `sr_max_channels` — 값은 요청 데이터(ADR-0009), 전략 1호 정의값 = 원본 기본값
  (10 / 5% / 290 / 1 / 5).
- **원본과 다른 유일한 부분**: 피벗은 우측 prd 봉 경과 후 확정(point-in-time 강제).
  원본 포팅본들은 과거 일괄 계산이라 이 지연을 안 지킨다 — 그건 백테스트 look-ahead 다.
- 구 §1(고정 % 군집·평균 단일선)·표시용 최근접 선별(`nearest_per_target`)·사이클 구간
  슬라이스는 폐기 — 원본 규격이 개수(최대 5존)를 이미 제한한다.
- **목표가 후보의 피보 구간 필터(78.6% 레벨~고점)는 유지** — 존은 최근 loopback 봉
  전체에서 나오므로, 필터 없이는 되돌림 목표가가 사이클 밖 존(수년 전 심저가 등)에
  스냅된다(backtest-validator 지적으로 복원, 회귀 테스트 고정). 화면 표시는 존 전체.
- 존 폭 기준 300봉·강도 가중 20점은 원본 Pine 소스에도 입력이 아닌 고정값 —
  FIB_RATIOS 와 같은 "계산 방법의 일부"(ADR-0009 §4 예외)로 상수 유지.
- 화면: 존 = 반투명 띠 + 중앙 점선, 라벨 "지지저항 (고점·저점 N개)".
- **목표가 스냅 대표값 = 존 중앙**((top+bottom)/2, 같은 저자 Dynamic v2 도 중앙에 선을
  긋는다) — **오너 확정 2026-08-06** (존 경계 대안 대비 중립·단순).

   전략 1호 외 기법의 시뮬 의미는 미정.

## 2차 개정 (2026-08-08) — 지지저항은 피보나치 선 근처만 본다

**무엇이 잘못됐나.** 지지저항을 피보나치와 **아무 상관없이** 따로 찾아 그렸다. 오너 지적:

> "피보나치 23%, 38% 50% 61% 78% 이거랑 지지저항 있는 게 안맞잖아. (…) 지금 가격이
>  25만 150만 하는데 5만원에다가 지지저항을 긋고 지랄하냐."

실측으로 재현했다(기준일 2026-08-04, 옛 설정 그대로):

| 종목 | 현재가 | 피보나치 선 | 그때 나온 지지저항 |
|---|---|---|---|
| 삼성전자 | 240,000 | 298,508 / 251,496 / 213,500 / 175,504 / 121,408 | **67,500~74,000** · 209,000~223,000 · 370,000~374,500 · 167,000~167,300 · 112,400 |
| SK하이닉스 | 1,577,000 | 2,320,465 / 1,908,117 / 1,574,850 / 1,241,583 / 767,100 | **245,000~306,500** · 525,000~646,000 · 806,000~931,000 · 1,060,000~1,099,000 |

원인 둘. (1) 탐색 구간이 **최근 290봉 고정**인데 그 사이 삼성전자가 53,800 → 374,500
(7배)이 됐다 — 작년 가격대의 자리가 지금 가격대의 자리와 같은 자격으로 뽑혔다.
(2) 피보나치 선을 아예 안 봤다. 매수·매도는 피보나치 선에 거는데 지지저항은 딴 데서
나오니 둘이 만날 이유가 없었다.

**새 규칙 (오너 2026-08-08).**

> "피보나치 선 근처의 지지저항의 라운드 피겨"

세 조건을 따로 채점하지 않는다. **순서대로 좁혀 들어간다.**

1. 피보나치 선마다 위아래로 띠를 친다 (`fib_zone.band_half`).
2. 그 띠에 걸치는 **지지저항 존**만 남긴다. 없으면 그 선엔 띠가 안 붙는다.
3. 띠와 존이 겹치는 구간 안의 **라운드 피겨**가 주문 가격이다. ±호가는 ② 매매전략.

피보나치 선 자체는 조건과 무관하게 **항상 5개 다 그린다** — 오너: "피보나치 선을 왜
지워. 피보나치는 피보나치대로 보여줘야지."

**띠 폭 (3택, 화면 입력).** 오너가 차트 보며 고른다.
`자동` = 하루 변동폭(ATR 10, 잔파동 기준과 **같은 정의**)의 N배 / `파동폭` = 바닥→꼭대기
폭의 N% / `가격` = 그 선 가격의 N%. 기본 자동 0.5배. 조사(2026-08-08) 결과 실제 구현체
다수가 ATR 배수를 쓴다(Boroden 가격 뭉치, LuxAlgo S/R Zones). 고정 %는 라운드 피겨를
거의 못 잡는다 — 삼성전자 50% 선(213,500)에서 가격 0.5%면 ±1,068 이라 210,000 을 놓친다.

**탐색 범위 (3택, 화면 입력).** `파동 구간`(기본, 파동 바닥 이후만) / `최근 N봉`
(`sr_loopback`) / `띠 안만`(전 구간에서 찾고 띠 밖은 버림). `sr_loopback` 기본값은
290 → **120** 으로 낮췄다(위 실측 근거).

**라운드 피겨 = 앞 두 자리** (`tick_size.round_unit`, 오너 규칙).
"215,000 이면 22만이나 21만이고 176,000 이면 18만이나 17만이지" — 사람이 의식하는 가격은
호가단위가 아니라 **가격의 자릿수**로 정해진다. 옛 방식(호가단위 ×10/100/1000)은
215,000 을 5,000 단위로 봐서 21만·22만이 안 나왔다.
근거: Osler(2003, *Journal of Finance* 58(5)) — 익절 주문은 라운드 숫자에 몰리고
손절은 그 바로 너머에 몰린다.

**지지저항 찾는 방법은 안 바꿨다.** 오너가 "사람들이 가장 많이 채택하는 것"을 요구해
다시 조사한 결과(2026-08-08) 우리가 쓰던 게 표준의 주류 구현이 맞았다:

- Murphy 교과서: "지지 = 직전에 되돌아 올라간 저점, 저항 = 직전 고점" → **꺾인 지점**
- Bulkowski 7가지 목록에 골짜기·봉우리·라운드넘버가 있고 **볼륨 프로파일은 없다**
- MT4/5 기본 "Fractals", TradingView 기본 "Pivot Points High Low" 둘 다 꺾인 지점
- LonesomeTheBlue SR Channels(우리가 포팅한 것) 부스트 326·조회 158만, MPL-2.0
- LuxAlgo 인기 지표(좋아요 277·조회 225만)도 알맹이는 같은 `pivothigh/pivotlow`
- TA-Lib·pandas-ta 에는 지지저항 함수가 **아예 없다** — 라이브러리 표준은 없다

볼륨 프로파일(매물대)은 **분봉이 있어야** 계산된다(TradingView 공식 문서). 우리는
일봉뿐이라 근사밖에 안 되고 교과서·논문 비교 기준선에도 없어 채택하지 않았다.
최소 꺾인 지점 수는 **1개**(원본 기본값, 오너 확정).

**새 전략 "지지저항만 보기"** (`sr_only`, `src/layer3_strategy/sr_overlay.py`).
오너 요청: "지금까지의 피보나치와 아예 상관없이 기준일 기준 왼쪽으로(미래는 못본다)
지지저항만 볼 수 있는 것도 가능한가?" → 별도 전략으로 추가. 찾는 함수는 피보나치 쪽과
**같은 `find_channels`** 다. 존마다 그 안의 라운드 피겨를 라벨에 싣는다.

**차트에서 전략을 고르는 UI 를 새로 만들었다** (`ChartStrategyBar.tsx`). 서버 카탈로그
(`/api/strategies`)를 받아만 두고 쓰는 화면이 없어서, 지지저항을 보려면 ③ 시뮬레이션까지
들어가야 했다(오너 지적: "또 시뮬레이션 탭에 다 때려 넣고 있는 거 아니지?").
폼은 ① 종목선정과 **같은 코드**(`ParamInputs`)를 쓴다 — 전략을 추가해도 화면은 안 고친다.

**폐기.** 목표가 후보의 "피보 구간(78.6%~고점) 필터"는 필요 없어졌다 — 애초에 피보나치 선
띠 안에서만 존을 찾으므로 파동 밖 존이 후보에 들어올 수 없다. "존 중앙을 목표가로"도
폐기: 목표가는 그 띠 안의 라운드 피겨다.

**확인(브라우저 실측 2026-08-08).** 삼성전자 기준일 2026-08-04 —
50.0% 선에 띠(209,000~223,000, 꺾임 2) → 매수 1차 **210,000**,
61.8% 선 → 2차 **170,000**, 78.6% 선 → 3차 **110,000**. 전부 라운드 피겨다.
24만원짜리 종목에 6~7만원대 선은 더 이상 안 나온다.

## 3차 개정 — 띠는 피보나치 선에, 지지저항은 선으로 (2026-08-09)

> "지금 회색 배경색으로 밴드가 그려져 있는데, 왜 지지저항에 그려져있지?
> 그리고 왜 지지저항마다 그 두께가 다른거야?" — 오너

**틀린 그림이었다.** 회색 띠의 위아래는 밴드가 아니라 `FibZone.bottom/top`, 즉 그 밴드
안에서 **방향이 바뀐 지점들의 아래끝~위끝**이었다. 자리마다 지점 개수와 흩어진 정도가
다르니 두께가 제각각일 수밖에 없다. 지점이 하나면 두께가 0이었다.

고친 모양:

| | 전 | 후 |
|---|---|---|
| 밴드(반투명 띠) | 지지저항에 붙음, 두께 제각각 | **피보나치 선**에 붙음, 다섯 선 두께가 같다 |
| 지지저항 | 방향 바뀐 지점들의 한가운데에 선 + 띠 | **주문에 쓸 라운드 가격 자리**에 선만 |

밴드는 "그 선을 어디까지 그 자리로 볼지" 정한 폭이라 한 방식으로 재고, 그래서 두께가
고르다(자동·파동폭 방식은 다섯 선이 정확히 같고, 가격 방식만 선 가격에 비례한다).
지지저항 선을 라운드 가격 위에 놓은 이유는 라벨에 적힌 숫자와 선이 어긋나면 어느 쪽이
진짜인지 알 수 없어서다.

API 계약도 따라 바뀐다 — `top`/`bottom` 은 이제 `kind: "fib"` 에 실린다.
차트 도구(`GET /api/support-resistance`, `sr_overlay`)는 그대로 띠다. 그쪽 띠는 묶인
지점들이 실제로 차지하는 폭이라 두께가 다른 게 맞다.

## 매수·매도는 선이 아니라 화살표 (2026-08-09)

> "매수 매도는 선으로 긋지 말고 화살표로만 한 뒤, 그 아래와 위에 숫자로 얼마에 사고
> 팔았는지를 적는 걸로 바꾸자." — 오너

화면을 가로지르던 매수·매도선을 없앴다. 체결은 그 봉 위에 화살표 + 체결가 + 차수로,
아직 안 걸린 목표가는 오른쪽 끝에 ◀ + 가격으로 그린다. 손절선은 "여기 깨지면 끝"이라
가로선으로 남겼다.

## 4차 개정 — 차트 기능 지지저항 전면 수정 (2026-08-09)

> "기본적으로 지지저항이 왜 낮은 가격대에만 있지? 삼성전자를 왜 25만원 쯤에 못 긋는
> 거야? SK 하이닉스는 120만원에 못 긋네."
> "차트 기능 상으로는 지금 차트에서 보이는 봉 갯수 내에서의 지지저항을 다 그려줘야지."
> — 오너

원인이 넷이었다. 전부 차트 기능(`sr_overlay`) 쪽이고, 피보나치 기법(`fib_zone`)은 건드리지
않았다 — 오너 2026-08-09: "지금이 피보나치 딱 좋아."

### 1. 자리 폭이 절대 금액이라 싼 구간이 통째로 한 덩어리

원본은 폭을 (최근 300봉 가격폭) × % 로 잰다. 화면 안에서 몇 배씩 오르는 종목에 안 맞는다.

| 종목 | 300봉 가격폭 | 폭 5% | 바닥에서 | 꼭대기에서 |
|---|---|---|---|---|
| 삼성전자 | 53,700~374,500 | 16,040원 | **32.1%** | 4.3% |
| SK하이닉스 | 196,500~2,987,000 | 139,525원 | **96.4%** | 4.7% |

바닥 자리가 그 구간 꺾임점을 다 삼켜 강도(피벗×20)가 폭발하고 상위를 독식했다.
→ 폭을 **그 자리 가격의 %** 로. 기본 2%.

### 2. 개수 상한 5개

강도 상위 5개만 남기니 위쪽 자리가 전멸했다. → `max_channels=None` 이면 전부.
실측 200봉에서 종목당 28~31자리.

### 3. 좌우 10봉이라 최근 자리를 놓침

21봉 창에서 제일 높아야 인정. → 좌우 5봉(피보나치 쪽과 같은 근거).

### 4. 후보가 꺾임점뿐 — 오너가 보는 자리가 애초에 후보가 아니었다

| 오너가 본 자리 | 실제 정체 | 꺾임점인가 |
|---|---|---|
| 삼성전자 250,000 | 2026-05-06 갭 상승 시초가 254,000 (전일 232,500, +9.2%) | ✗ |
| SK하이닉스 120만 | 2026-04-21~24 나흘 저가 1,193,000·1,195,000·1,183,000·1,193,000 | ✗ |

하이닉스는 나흘 내리 같은 값에서 받쳤는데 **연속이라** 좌우 5봉 창의 최저가 아니었다.
사람은 "여러 번 닿았다"를 보지 "좌우 5봉 최저"를 보지 않는다.

→ 후보를 **모든 봉의 고가·저가**로 넓혔다(`SEED_ALL`, 차트 기능 기본).
`min_turns`(이만큼은 닿아야 자리로 친다) 기본 5.

결과(200봉, 폭 2%, 최소 5회):

| 종목 | 자리 수 | 오너가 본 자리 |
|---|---|---|
| 삼성전자 | 28개 | **246,000~251,000** (5번 닿음, 라운드 250,000) ✓ |
| SK하이닉스 | 31개 | **1,173,000~1,195,000** (5번) · 1,228,000~1,249,000 (5번) ✓ |

'꺾임점'만 쓰는 옛 방식은 `sr_source` 로 남겨 뒀다.

### 라벨 겹침

자리가 28~31개면 오른쪽 라벨이 포개져 아무것도 못 읽는다. **선은 다 그리고 라벨만**
앞 라벨과 13px 안에 붙으면 건너뛴다(`ProChart.drawLines`).

## 5차 개정 — 오더블록·가격 빈틈(FVG) 추가, 후보 정의 통일 (2026-08-09)

> "그 지지저항을 스윙 프렉탈, 오더블록, FVG 관련해서는 적용할 필요 없나?
>  특히 오더블록과 FVG. 그리고 이미 쓰이는 곳이 있나?"
> "피보나치를 손댈 게 아니라 지지저항을 손 대야지." — 오너

### 이미 쓰던 것 / 없던 것

**스윙 프렉탈은 이미 쓰고 있었다** — `support_resistance` 의 `sr_prd`(좌우 N봉에서 최고·
최저)가 트레이딩뷰 `pivothigh/pivotlow`, MT4/5 "Fractals" 와 같은 계산이다.
**오더블록·FVG 는 코드에 없었다.** 시장 구조 판정(상승/하락 전환)만 같은 SMC 계열로 있었다.

### 셋이 서로 다른 자리를 짚는다 (실측 2026-08-04, 200봉)

| 오너가 본 자리 | 여러 번 닿음 | 오더블록 | 가격 빈틈 |
|---|---|---|---|
| 삼성전자 250,000 | ✓ 246,000~251,000 | ✓ 243,000~263,500 (26-07-21) | ✗ |
| SK하이닉스 120만 | ✓ 1,173,000~1,195,000 | ✗ | ✗ |

겹치지 않으므로 **따로 켜고 끈다**(오너 결정). 도구 막대에 `[지지저항] [오더블록]
[가격 빈틈]` 세 버튼, 색은 회색 / 보라 / 청록.

구현 `src/layer3_strategy/price_zones.py`, 조회 `GET /api/price-zones?kind=...`.
정의는 공개된 표준을 보고 직접 구현했다 — **LuxAlgo Pine 소스는 안 봤다**(CC BY-NC-SA).

- 오더블록 = 세게 밀어낸 봉 **직전의 마지막 반대색 봉**. 되돌아와 반대편으로 완전히
  통과하면(뚫리면) 뺀다.
- 가격 빈틈 = 세 봉에서 1번봉과 3번봉이 안 겹치는 구간. 메워지면 뺀다.

### 후보 정의를 피보나치 쪽과 통일

피보나치 기법의 지지저항도 `sr_source` 를 쓴다. 기본은 차트 기능과 같은 '고가·저가 전부'.
꺾임점만 보면 되돌림 선 다섯 개 중 두세 개가 비어 매수 차수를 다 못 걸었다:

| 종목 | 꺾임점만 | 고가·저가 전부 |
|---|---|---|
| 삼성전자 | 3/5 | **5/5** (38.2%→260,000 · 61.8%→200,000 추가) |
| SK하이닉스 | 4/5 | **5/5** (61.8%→1,300,000 추가, 50%는 1,700,000→1,600,000) |
| 현대차 | 3/5 | **5/5** (23.6%→650,000 · 78.6%→340,000 추가) |

### 성능 (삼성전자, 전체 7,872봉 보유)

보는 구간은 **화면에 보이는 봉 수** 그대로다(오너: "화면에 봉 갯수 설정하는 거 있잖아
딱 그정도 까지만"). 별도 상한을 두지 않았다.

| 화면 | 지지저항 | 오더블록 | 가격 빈틈 |
|---|---|---|---|
| 200봉 | 16 ms (28자리) | 1 ms (8) | 2 ms (13) |
| 500봉 | 37 ms (47) | 1 ms (9) | 2 ms (26) |
| 1000봉 | 51 ms (51) | 1 ms (9) | 5 ms (26) |
| 전체 7872봉 | 1,053 ms (209) | 9 ms (24) | 35 ms (82) |

`전체`만 1초가 걸린다. 지지저항 후보가 봉 수의 제곱으로 늘기 때문인데(`_build_channels`
가 O(n²)), 그때 자리가 209개라 화면이 어차피 안 읽힌다. 실사용 구간(200~1000봉)은
전부 60ms 아래다.

### 이미 지나간 자리도 보여준다 (같은 날 추가)

> "메워졌다는 게 뭔 소리지. 일단 보이게 해봐." — 오너

용어가 안 통했다. 라벨을 무슨 일이 있었는지 그대로 적는 말로 바꿨다.

| | 무슨 뜻인가 | 라벨 |
|---|---|---|
| 가격 빈틈 | 되돌아와 그 구간을 위아래로 다 지나갔다 | `이미 다시 지나감` |
| 오더블록 | 되돌아와 그 봉의 저가(지지)·고가(저항)를 뚫었다 | `이미 뚫고 내려감` |

기본을 "살아 있는 것만"에서 **"전부, 지나간 건 흐리게"**로 바꿨다(`alive_only=false`).
선·띠 색을 40%로 낮추고, 라벨 자리는 **살아 있는 자리가 먼저** 가져간다.

삼성전자 200봉: 가격 빈틈 13 → **67**자리, 오더블록 8 → **23**자리.
빈틈 67개는 화면을 거의 덮는다 — 줄일지는 오너가 화면 보고 정한다.

선 라벨은 `가격 빈틈(FVG)` 로 원어를 병기한다(버튼은 짧게 `가격 빈틈`).

### 화면 오른쪽 끝 봉을 따라 자동 갱신 (같은 날)

> "화면에 보이는 맨 오른쪽 봉 기준으로 계속 갱신되게 할 순 없지?"
> "일반적인 HTS와 다르게 캔들에 영향없이 자유롭게 이동가능해서 어려울려나" — 오너

이미 되고 있었지만 구멍이 둘 있었다.

1. **부모 콜백이 없으면 갱신을 건너뛰었다.** `emitBase` 가 `onBaseBar` 가 없으면 통째로
   조기 반환해서, 그 prop 을 안 주는 차트 탭에서는 스크롤해도 자리가 그대로 남았다.
   → 도구 갱신을 부모 콜백과 분리했다.
2. **줌만 바꾸면 갱신이 안 됐다.** 오른쪽 끝 봉만 비교해서, 끝은 그대로고 왼쪽만 늘어난
   경우를 놓쳤다. → 판정 키를 `오른쪽 끝 봉 : 보이는 봉 수` 로 바꿨다.

캔들 없는 오른쪽 여백까지 미는 건 원래 문제가 안 된다 — `getVisibleRange().to` 가 데이터
개수를 넘으면 잘라서 **마지막 실제 봉**을 쓰므로 기준일이 거기서 멈춘다.

드래그 중 매 프레임 서버를 때리지 않게 250ms 쉰 뒤 한 번만 계산한다.

### 오더블록·빈틈 띠는 **생긴 봉부터 오른쪽으로만** (같은 날)

> "오더블록과 FVG도 밴드가 있는 게 이상하지 않아?" — 오너

띠 자체는 맞다 — 두 개념은 정의부터 구간이라 선으로 표현할 수 없다(오더블록 = 봉 하나의
저가~고가, 빈틈 = 갭 구간 그 자체). 표준 지표도 사각형으로 그린다.

틀린 건 **그리는 범위**였다. 화면 왼쪽 끝부터 가로로 다 칠해서, 그 자리가 생기기도 전인
과거 구간까지 덮였다(삼성전자 200봉 · 빈틈 67자리에서 화면이 통째로 청록이었다).
→ `OverlayLine.start` 를 실어 **그 봉부터 오른쪽으로만** 그린다.
지지저항·피보나치는 시점과 무관한 수평 자리라 그대로 화면을 가로지른다.

### 묶는 폭 2% 의 근거 — 없다

> "지지저항을 2%로 묶는 건 공식적인 연구가 있는 건가?" — 오너

**공식 연구에서 나온 값이 아니다. 내가 정했다.** 관련 선례는 있으나 성격이 다르다.

- 원본 지표(LonesomeTheBlue): 최근 300봉 가격폭의 5% — 절대 금액이라 우리 종목엔 못 쓴다
  (이 문서 4차 개정의 32%·96% 실측 참조).
- Brock·Lakonishok·LeBaron (1992), *Journal of Finance* 47(5): 거래범위 돌파 규칙에 밴드
  필터를 뒀다. 다만 그건 **돌파를 인정할지**를 거르는 값이지 자리를 묶는 폭이 아니다.
- 통화시장 tick 군집 연구(Nat. Accounting Review, 2020)도 tolerance 를 **조정 대상**으로
  두고 고정값을 권하지 않는다.

실측(2026-08-04, 200봉, 고가·저가 전부 · 최소 5회):

## 6차 개정 — 주문가는 굵은 숫자 우선, 차수 사이 최소 간격 (2026-08-09)

### 오너 지적

> "이거 61% 되돌림일 때 삼성전자 매수타점은 17만원이어야 하는데? 3월 4일 3월 9일 3월 31일
> 지지저항이 떡하니 있잖아. 왜 그걸 못찾아. 그리고 38% 되돌림 선에서는 26만원 보다는
> 25만원이 사람 심리적으로 라운드 피겨가 딱 맞아 떨어져서 더 맞는거고. 일단 20만원 22만원
> 이거 매수 타점이 너무 좁잖아. (…) 난 일단 -10%나 -15%의 차이는 넘게 봐야한다고 보는데."

### 원인 (삼성전자 기준일 2026-08-04 실측)

파동 70,550(2025-09-12) → 374,500(2026-06-19). ATR 27,421, 밴드 반폭 13,710.

| 되돌림 | 선 | 자리 | 옛 주문가 | 왜 |
|---|---|---|---|---|
| 38.2% | 258,391 | 246,000~270,000 | 260,000 | 선에 제일 가까워서 |
| 50.0% | 222,525 | 209,000~234,000 | 220,000 | 선에 제일 가까워서 |
| 61.8% | 186,659 | 174,700~200,000 | 200,000 | **10만 배수 하나뿐이라 후보가 하나** |

세 가지가 얽혀 있었다.

1. **`round_figures_between` 이 굵은 단위에서 멈춘다.** 174,700~200,000 에서 10만 배수인
   200,000 이 걸리자 거기서 끝나, 18만·19만이 후보에 오르지도 못했다. 이 규칙 자체는
   라벨을 읽기 좋게 하려고 넣은 것이라 옳다 — **주문가 고르기에 쓴 게 잘못이었다.**
2. **선에 가장 가까운 값을 골랐다.** 사람이 의식하는 건 거리가 아니라 자릿수다.
   250,000(5만 배수)이 260,000(1만 배수)보다 세다.
3. **차수 사이 간격 규칙이 없었다.** 200,000 은 자리의 맨 윗끝(선보다 +7.15%)이라
   50% 차수 220,000 과 9.1% 밖에 안 벌어졌다.

밴드 폭은 원인이 아니었다. 61.8% 밴드는 ±7.35%(172,949~200,369, 폭 27,420원)로 좁지 않다.
오너 확인: "이미 지금 폭도 넓은 편인데?" → **안 건드린다.**

### 결정

1. `tick_size.roundness(price)` — 그 가격을 나누어떨어지게 하는 가장 굵은 단위.
   10의 거듭제곱 사이에 절반 자리(5만·50만…)를 끼운다. 250,000 → 50,000.
2. `tick_size.round_figures_all_between()` — 주문가 **후보**는 굵은 데서 안 멈추고 전부.
   기존 `round_figures_between()` 은 **라벨 전용**으로 남는다.
3. `fib_zone.pick_order_price(candidates, fib_price, max_gap_pct)` — 굵은 순, 같은 굵기면
   선에 가까운 쪽, 그래도 같으면 낮은 쪽(보수). **선에서 `max_gap_pct`% 넘게 떨어진 값은
   제외.** 전부 멀면 None — 억지로 고르지 않는다.
   - 새 파라미터 `sr_round_max_gap_pct`, 기본 5%. 근거: 250,000 은 -3.25% 라 남고
     200,000 은 +7.15% 라 빠진다.
4. `entry_levels.buy_targets_sr(..., min_gap_pct)` — 다음 차수는 앞 차수보다 최소
   이만큼(%) 아래. 0 이면 안 쓴다(옛 저장본 호환).
   - ② 매매전략에 `차수 사이 최소 간격` 칸. 새 전략 기본 10%, **옛 저장본은 0** —
     이미 저장해 둔 전략의 계산 결과가 말없이 바뀌면 안 된다.

미래 데이터 훔쳐보기가 아니다. 오너 지시 "지지저항을 찾는 구간을 파동 끝이 아니라
기준일까지로 바꿔" — 이미 그렇게 돌고 있음을 확인했다(`fibonacci.pivots_for`,
`sr_scope='파동 구간'` = `d.loc[d["Date"] >= wave_start]`, 오른쪽 끝은 호출부가 자른 기준일).

## 차트 도구가 주봉·월봉에서 안 맞던 문제 (2026-08-09)

오너: "근데 지금 지지저항 고장났네. 동작 안하네."

일봉에서는 정상이었고 주봉·월봉에서 깨져 있었다. 원인 둘.

1. **주기를 바꿔도 도구를 다시 계산하지 않았다.** `pickPeriod` 가 `reload()` 만 부르고
   `refreshTools()` 를 안 불러, 일 → 주 → 월 로 바꿔도 이전 주기 값이 남았다.
2. **보이는 봉 개수를 그대로 보냈다.** 계산은 언제나 일봉인데 월봉 화면의 "200봉"은
   200달이다. 서버는 최근 200**일**로 알아들어, 1995~2026 이 보이는 월봉 화면에
   최근 200일 자리만 오른쪽 끝에 몰려 그려졌다.

수정: 봉 개수 대신 **화면 왼쪽 끝 봉의 날짜**(`start`)를 보낸다
(`api/main.py::_visible_bars`, `web/src/api.ts::VisibleWindow`). 어떤 주기에서도 보이는
구간과 정확히 같아진다. `bars` 는 `start` 를 못 구했을 때의 대비값으로 남긴다.

덤: 도구 버튼 두 개를 한 프레임 안에 누르면 두 번째가 첫 번째를 되돌리던 버그
(`toggleTool` 이 렌더 뒤에야 갱신되는 `tools` 를 읽었다) — ref 를 정본으로 바꿨다.

## 7차 개정 — 순서를 뒤집는다: 자리를 먼저 만들고 되돌림 선을 배정한다 (2026-08-09)

### 오너 지적

> "아니 도대체 왜 2월 12일 저가, 3월 9일, 3월 31일 저가를 고려를 못 하는 거야 대놓고
> 박스권 저점인데"
> "삼성전자를 기준일 26년 3월 19일로 잡았을 때도, 1월 27일부터 2월 11일까지가 박스권인게
> 딱 보이잖아. 그럼 지지저항을 16만원이 아니라 17만원에 그어져야지"
> "기존 로직 자체가 잘못 됐을 수 있다는 걸 생각해"

### 무엇이 잘못됐나

6차까지는 **밴드를 먼저 그리고 그 안에 든 봉들의 아래끝~위끝을 "지지저항"이라고 불렀다.**
그건 지지선이 아니라 밴드를 다시 그린 것이다. 자리를 **만드는** 단계가 없었다.

2차 개정에서 "밴드가 이미 어디를 볼지 정하므로 묶기·강도순·겹침 제거가 필요 없다"며 그
단계를 지운 게 원인이다. 밴드는 *어디를 볼지*만 정하지 *무엇이 자리인지*는 안 정한다.

업계에서 쓰는 순서는 반대다 (조사 2026-08-09):

```
표준     지지선을 먼저 찾는다 → 피보나치를 긋는다 → 선이 어느 자리에 떨어지나 본다
6차까지  피보나치를 긋는다 → 밴드를 두른다 → 밴드 안의 봉을 "자리"라고 부른다
```

### 실측 — 자리는 이미 잡히는데 피보나치 쪽이 안 봤다

차트 기능(`find_channels`, 폭 3%)을 파동 구간(2025-09-12~2026-08-04)에 돌리면:

| 모인 값 범위 | 평균 | 라운드 | 닿은 봉 | 그냥 지나간 봉 |
|---|---|---|---|---|
| 246,000~253,000 | 249,500 | 250,000 | 11 | 3 |
| 220,000~226,000 | 223,000 | 220,000 | 13 | 4 |
| 185,500~191,200 | 188,350 | 190,000 | 20 | 3 |
| **165,500~170,600** | **168,050** | **170,000** | 11 | **0** |

오너가 지목한 자리가 목록에 있다. 61.8% 선(186,659)의 밴드가 172,949~200,369 라
피보나치 쪽에서 그 자리를 **아예 못 봤을 뿐이다.**

오너가 짚은 아홉 값의 단순 평균도 168,800 → 라운드 170,000 으로 맞는다
(1/27~2/11 박스 천장 고가 169,400·168,700·168,600·168,100·167,500 +
그 뒤 저가 167,300·172,000·170,600·167,000). 오너: "단순하게 평균 내는 건 정답이 아닌거야?"

### 결정

1. **`fibonacci.pivots_for` → `levels_for`.** 가격 목록이 아니라 **지지선·저항선 목록**을
   만든다. 차트 기능과 **같은 함수**(`find_channels`)를 쓴다 — 두 화면이 같은 자리를 본다.
   새 파라미터 `sr_channel_width_pct`(한 자리로 묶는 폭, 전략 기본 3%).
2. **`SRChannel.avg` 추가** — 그 존에 들어온 고가·저가의 평균. 대표 가격은 이제 이쪽이다.
   `mid`(상단·하단 한가운데)는 남기되 "대표값으로 쓰지 말 것"으로 표시.
3. **`find_fib_zones` 가 자리 목록을 받는다.** 되돌림 선이 자리 **안**이면 그 자리,
   자리 사이 **빈틈**이면 **바로 아래 자리**. 아래에 자리가 없으면 그 차수는 비운다
   (위쪽 자리를 주면 추격 매수다).
4. **주문가 후보가 자리 안에 없으면 자리 밖 `sr_round_max_gap_pct`% 까지** 본다.
   비싼 종목은 라운드 단위가 자리 폭보다 굵다 — SK하이닉스 50% 자리
   1,630,000~1,678,000 에 10만 배수가 없어 주문가가 안 나왔다.
5. **차트 기능 라벨에도 같은 처리**(`sr_overlay.round_prices_for`, 자리 밖 0.5%).
   166,500~169,400 에 "라운드 170,000" 이 붙는다 — 오너가 본 "16만" 문제의 원인.

### "빈틈이면 아래 자리" 를 왜 "가장 가까운 자리" 대신 쓰나

되돌림 선이 자리 사이 빈틈에 걸리면 "가장 가까운 자리"는 날마다 뒤집힌다. 삼성전자
38.2% 선 258,391 은 253,000 과 260,000 사이에 있어 250,000 ↔ 260,000 을 오갔다.

오너: "날마다 타점이 바뀌는 게 맞긴 해. 지지,저항선이 최근 정보에 따라 갱신되는 거 아니야?"
— 갱신은 맞다. **되돌아오는 게** 새 정보가 아니다.

기준일을 하루씩 넘긴 실측 (2026-06-22~08-04, 31거래일 × 3종목 × 3차수 = 279칸):

| | 6차까지 | 7차 |
|---|---|---|
| 값이 바뀐 횟수 | 여러 번, 되돌아옴 | 종목당 **1번**, 되돌아온 적 없음 |
| 삼성 38.2% | 250,000 ↔ 260,000 반복 | 220,000 → 250,000 (7/14) 후 고정 |
| 삼성 50%·61.8% | 고정 | 고정 |
| 하이닉스 61.8% | — | 없음 → 1,300,000 (6/25) 후 고정 |
| 현대차 61.8% | — | 420,000 → 430,000 (7/14) 후 고정 |

### 결과 (기준일 2026-08-04)

| 되돌림 | 삼성전자 | SK하이닉스 | 현대차 |

### 61.8% 는 190,000 이고, 그게 맞았다

오너는 170,000 을 원했지만 실측으로 확인한 결과 **190,000 이 옳았다.**

꼭대기(2026-06-19 374,500) 이후 실제 흐름:

유일한 자리)는 BORB-75 에 남긴다.

### 오더블록·가격 빈틈

에이전트 실측: 오더블록 **2026-03-31 167,000~174,700** 이 오너가 짚은 자리를 정확히
짚는다(61.8% 기준 오차 0.5%). 그러나 38.2%·50% 에서는 오더블록·빈틈이 지지선보다
5~7% 벗어나 오히려 나빠진다. 15개 지점 중 절반만 지지선과 같은 자리를 짚었다.
**타점 계산에 넣지 않는다.** `fibonacci.band_zone_lines` 는 여전히 죽은 코드다(BORB-76).

## 5차 개정 — 매도는 지지/저항에 안 붙인다 (2026-08-10)

> "평단은 평단 기준인 거지 왜 지지저항선에 매도를 거냐..? 그럴거였으면 내가 매도 전략
> 탭에서 피보나치 선 기준이라고 했겠지" — 오너

§2의 "가장 가까운 지지/저항선에 ±호가" 규칙을 **매수에만** 남긴다. 매도 지정가는
화면(② 매도 탭)이 약속한 그대로 **기준가(평단·최저 체결가·파동 꼭대기) × (1+반등%)** 를
호가에 맞춘 값(올림 — 체결이 덜 되는 보수 방향)이다. `entry_levels.sell_targets_sr` 는
삭제, 계산은 `fills._sell_prices` 한 곳이다(③ 시뮬레이션·④ 백테스트 공용).

부수 효과: "평단 위에 지지/저항선이 없으면 매도 주문이 조용히 안 걸리던(None) 구멍"이
사라진다 — 기준가만 있으면 항상 걸린다. (ADR-0017의 안팔림 증상 절반이 이거였다.)
