# ADR-0010: KIS 브로커 어댑터 (조회 전용)

- **상태:** 수락 (조회 전용 / 주문 전송 미착수)
- **날짜:** 2026-08-05
- **관련:** CLAUDE.md(주문 창구 = KIS, 단계 5·6), ADR-0002(수급 소스 미정), BORB-33/34, MCP 사용 규칙

## 맥락 (Context)

주문 창구는 KIS 로 정해져 있다(CLAUDE.md). 그런데 KIS 오픈API 는 주문만 주는 게 아니라
조회도 준다. 지금 필요한 건 조회 쪽이다.

세 가지가 걸려 있었다.

1. **수급 데이터 소스가 미정이다**(ADR-0002 부분 수락, BORB-33/34/35/36). 외인·기관·개인
   순매수는 거래소가 집계하는 정보라 우리가 계산으로 만들 수 없다. KIS 가 후보인데,
   후보인지 아닌지 판단하려면 실제로 호출해봐야 한다. 어댑터가 먼저다.
2. **증권사만 가진 데이터가 있다.** HTS 조회상위처럼 "사람들이 실제로 뭘 많이 봤는가"는
   가격 데이터로 재현할 수 없다.
3. **MCP 는 이 경로에 못 들어온다.** `kis-code-assistant` MCP 는 개발 시점 API 검색 보조일
   뿐이고, 조회·주문을 수행하는 서드파티 KIS MCP 를 실행 경로에 연결하는 것은 금지다
   (CLAUDE.md). 실행은 우리 코드가 한다. 그래서 직접 짠다.

## 결정 (Decision)

`src/layer4_execution/brokers/kis/` — 조회 전용 어댑터. 브로커 연동은 Layer 4 다.

1. **세 겹으로 나눈다.** `auth`(토큰 발급·캐싱) / `client`(헤더 조립·실패 판정) /
   `quotes`(TR 별 응답 파싱). KIS 는 엔드포인트가 200 개가 넘는데 인증 헤더와 실패 규칙은
   전부 같다. 조회 함수마다 헤더를 만들면 한 칸씩 어긋난다.

2. **주문 전송은 넣지 않는다.** `hashkey` 도 없다. 실전 앱키로 조회는 하되 주문은 모의투자
   확보 후에 붙인다(CLAUDE.md 단계 6). 붙일 때 새 ADR 을 쓴다.

3. **토큰은 파일로 캐싱한다.** KIS 공식 샘플(`examples_llm/auth/auth_token`)에는 캐싱이 없어
   호출마다 새로 발급한다. 발급에는 호출 제한이 있어서 샘플대로 짜면 개발 중에 계속 막힌다.
   캐시 파일 `kis_token.json` 은 `.gitignore` 등재.

4. **캐시에 앱키 원문을 쓰지 않는다.** 환경(`real`/`vts`)과 앱키 sha256 앞 12 자리 지문만
   적고, 둘 중 하나라도 다르면 캐시 미스로 본다. 실전 토큰을 모의 서버에 쏘면 인증이
   조용히 깨진다.

5. **실패 판정은 `rt_cd` 로 한다.** KIS 는 토큰 만료·권한 없음 같은 실패에도 HTTP 200 을
   주고 본문 `rt_cd` 로만 알린다. 이걸 안 보면 **실패가 빈 결과로 둔갑하고, 전략이
   "오늘은 신호가 없다"로 오판한다.** HTTP 실패와 `rt_cd != "0"` 을 같은 예외로 모은다.

6. **만료 시각은 `expires_in`(초)으로 계산한다.** 응답의 `access_token_token_expired` 는
   KST 문자열인데 타임존 표기가 없어 서버/로컬 시차에 취약하다. 만료 10 분 전부터 만료로
   본다 — 몇 초 남은 토큰으로 요청을 보내면 도중에 만료된다.

7. **네트워크를 주입으로 갈아낀다.** `transport`(client)와 `issue`(auth)를 인자로 받아
   캐싱·파싱·실패 판정 테스트가 네트워크 없이 돈다.

8. **자격증명은 `.env` 에서만 온다.** 코드 하드코딩 금지, 예시는 `.env.example`.

## 결과 (Consequences)

- 수급 데이터 조사(BORB-33/34)를 문서 읽기가 아니라 실제 호출로 할 수 있다.
- **HTS 조회상위는 백테스트에 바로 못 쓴다.** 이 API 는 "지금 이 순간의 상위 20"만 주고
  과거 특정일을 되돌려 받을 수 없다. point-in-time 재현이 불가능하므로 신호로 채택하려면
  지금부터 주기적으로 찍어 시계열을 쌓아야 한다. 쌓기 전에는 look-ahead 없는 검증이
  성립하지 않는다. 수집기는 아직 없다.
- 연속조회(`tr_cont`) 페이지 순회는 호출 쪽에 남겨뒀다. 클라이언트가 감추면 몇 페이지를
  실제로 받았는지 호출 쪽이 모르게 된다.
- 조회 경로가 생겼다고 해서 매매 판단이 여기로 오는 것은 아니다. 어댑터는 데이터를
  가져오기만 한다.
