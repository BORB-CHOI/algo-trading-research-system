# ADR-0019: ATS 정체성 v4.0 — 확인하는 시스템 + 전략 9단 계층

- **상태:** 수락
- **날짜:** 2026-08-16
- **관련:** PROJECT_GUIDELINES v4.0 전체 / ADR-0001(폐기) · ADR-0009 · ADR-0012 · ADR-0018
- **근거 문서:** `ATS_REAL_MISSION_FINAL.md` (오너 제공, 2026-08-15),
  `docs/superpowers/specs/2026-08-16-ats-v4-design.md`

## 맥락 (Context)

지침서 v3.8(4,134줄)은 세 가지를 사실로 전제했는데, 셋 다 확인된 적이 없다.

1. **"AI와 조건 라이브러리를 쌓으면 시스템이 영원히 진화한다."**
   실제로 하고 있는 일은 진화가 아니라 **확인**이다.
2. **"4요소(기술적 통계 + 재료 해석 + 시장 심리 + AI 판단)를 결합하면 손익비가 비대칭이 된다."**
   이건 시스템의 존재 이유가 아니라 확인할 주장 중 하나다. 'AI 판단'은 아예 요소에서 빠진다.
3. **"고수의 중요도 순위(시황 > 투자심리 > 주도주 …)를 시스템 가중치에 반영한다."**
   순위 자체가 주장이다.

v3.8 전 구간을 미션 문서와 대조한 결과 **정면 충돌 183곳**이 나왔고,
§7(영원한 진화)·§10~13·§3.1~3.8에 몰려 있었다.

또 하나, 실제 작업에서 반복된 문제가 있다. **AI가 오너의 자리에 앉는 것** —
어떤 조건으로 종목을 거를지, 무엇을 먼저 확인할지, 어떤 구간을 볼지를 AI가 정하려 했다.
이 설계서 초안(2026-08-16 오전)도 같은 실수를 했고 오너가 지적했다.

## 검토한 선택지 (Options)

### A. 증분 정정만 (v3.8이 쓴 방식)

add/correct만 하고 통삭제 없음. 충돌 문장에 정정 주석을 단다.

- 장점: 잃는 게 없다. CLAUDE.md "디테일 보존" 규칙에 가장 안전
- 단점: 4,134줄이 더 길어진다. **새 정체성이 옛 서술에 묻힌다.**
  실제로 v3.8이 이미 그렇게 됐다 — 확인 안 된 조건 35개가 "조건 라이브러리"라는
  이름으로 확정 도구처럼 읽혔다
- 가드레일 위반: 없음

### B. 짧게 새로 쓰고 v3.8은 통째로 버림

- 장점: 가장 깔끔
- 단점: 발언 출처·수식·학술 근거·yaml 정의를 잃는다.
  **CLAUDE.md "큰 삭제·구조 변경 전 확인, 기존 디테일·근거는 의심스러우면 보존" 위반**
- 가드레일 위반: 있음

### C. 핵심 재작성 + 본문은 원재료로 이관 (채택)

- 지침서는 **확정된 원칙만** 담아 짧게 다시 쓴다 (4,134 → 686줄)
- v3.8 원본은 `docs/archive/` 에 **바이트 단위로 동일하게** 보존
- 본문의 조건 35개·재료 5축·반전 4종·회피 6가지·트리거 Tier는
  `docs/hypotheses/` 로 옮겨 **"확인 대기 원재료"** 로 격하 (삭제 ❌)
- 장점: 새 정체성이 선명해지고, 자산은 전부 남는다
- 단점: 파일이 늘어난다 (7개)
- 가드레일 위반: 없음 (삭제가 아니라 이관)

## 결정 (Decision)

### 1. 정체성

> ATS는 검증된 트레이더(실전 10년+, 큰 자금 운용)의 매매 관점과 발언을 하나하나 확인할 수
> 있는 주장으로 바꾸고, 한국 증시 과거 데이터로 그게 실제 미래 수익과 관계가 있는지
> 확인한다. 시장 상황·종목 상태·매매 유형별로 통하는 전략을 찾고, 사용자가 최종 승인한
> 매매 계획만 예약 매수·매도 주문으로 자동 실행하며, 그 전략의 힘이 약해지는지 지켜보는
> 알고리즘 매매·연구 시스템이다.

"영원한 진화" → **"힘이 약해지면 새 연구가 필요하다고 알려 주는 것"**으로 대체.

### 2. 역할 경계 (타협 불가)

| 누가 | 무엇을 |
|---|---|
| 사람 | 무엇을 확인할지 · 조건과 임계값 선택 · 검사 구간 · **최종 승인** |
| AI | **코딩** · **글 해석** · **시키면 계산 돌리고 보고** |
| 시스템 | 데이터 · 선별 · 백테스트 · 체결 흉내 · **승인 후** 주문 실행 |

**AI는 조건·임계값·우선순위·검사 구간을 정하지 않는다.**
AI의 일은 "오너가 그걸 화면에서 고를 수 있게 만드는 것"이다.

### 3. 전략 9단 계층

```
종목 선정 → 시장 상황 → 전략군 → 모양 → 진입 → 비중 → 청산 → 위험 관리 → 실행
```

### 4. "그때 알 수 있었던 정보만" 원칙을 모든 값에 적용

v3.8은 이 원칙을 종목 목록에만 걸었다(`point-in-time universe`).
v4.0에서는 **가격·시총·수급·뉴스·주도주·신고가·재무 전부**에 건다.

용어도 바꾼다: `point-in-time universe` → **"당시 기준 종목 목록"**,
`look-ahead` → **"미래 데이터 훔쳐보기"**, `survivorship bias` → **"살아남은 것만 보는 착시"**.

### 5. 문서 구조

```
docs/PROJECT_GUIDELINES.md          v4.0, 686줄 — 확정된 원칙만
docs/hypotheses/*.md (7개)          확인 대기 원재료 (우선순위·검증계획 ❌ — 오너 몫)
docs/archive/PROJECT_GUIDELINES-v3.8.md   원본 통째 보존
```

### 6. 검사 구간

**코드가 구간을 강제하지 않는다.** 화면에서 고른 날짜가 그대로 검사 구간이다.
기본값만 `2007-01-01 ~ 최신 거래일` (리먼 사태 2008-09-15 전부터 보기 위해).
옛 3분할(SPLITS)은 쓰지 않되 지우지 않는다 — 옛 보관함 기록이 그 이름을 가리킨다.

**모든 정량값은 임시값이다.**

## 결과 (Consequences)

### 뒤집지 않는 것 (중요)

**기존 전략 ADR을 하나도 뒤집지 않는다.** 코드도 지우지 않는다.
바뀌는 것은 **계층상 위치와 부르는 이름**뿐이다.

| 계층 | 지금 코드 | v4.0 이름 |
|---|---|---|
| 전략군 | — | 상승 사이클 눌림매매 |
| 모양 | `market_structure.py` · `zigzag.py` · `surge.py` | 오름 구간 이후 눌림 |
| 진입 | `fibonacci.py` · `entry_levels.py` · `fib_zone.py` (ADR-0011·0013) | 피보나치 되돌림 진입 모델 |
| 청산 | `support_resistance.py` · `fills.py` · `stops.py` (ADR-0014) | 지지/저항 존 분할 매도 |
| 실행 | `strategy_one.py` · `walk_forward.py` (ADR-0015·0017) | 백테스트 실행 하네스 |

즉 "전략 1호 = 피보나치"가 아니라 **"상승 사이클 눌림매매"라는 전략군의 진입 방법 하나가
피보나치**다. **격하가 아니라 승격이다** — 같은 전략군에 형제 진입 방법(전고점 지지 /
이동평균 / 거래대금 기반)을 끼워 넣을 자리를 만드는 것이 목적이다.

유지되는 ADR: 0002 · 0003 · 0004 · 0005 · 0006 · 0007 · 0008 · 0009 · 0010 ·
0011 · 0012 · 0013 · 0014 · 0015 · 0016 · 0017 · 0018.
(ADR-0001은 v4.0 이전에 이미 폐기됨 — 종가 진입 전제)

### 후속 작업

- 구간 강제 제거 + 기본값 2007~ (`backtest.py` · `api/main.py`)
- 조건검색식에 순위 기준 추가 (시총 상위 N% · 거래대금 상위 N위) — 화면 선택지
- 체결이 얼마나 아슬아슬했는지 기록 (`fills.py` · `strategy_one.py`)
- 실험 산출물에 체결 내역 추가 (`run_store.py`)
- 데이터 창구 분리 + 수급 결손 알림 (`layer1_data/provider.py`)
- 레포 이름 `algo-trading-research-system` 으로 변경

### 이 결정으로 드러난 데이터 사실 (고치지 않고 기록)

- **지침서·CLAUDE.md의 "데이터 2017-01~현재"는 틀린 서술이다.**
  marcap은 1995~2026, 빠진 해 0. 수정주가 일봉 5,478종목
- **수급 데이터에 상장폐지 종목이 통째로 없다** — 595개 중 0개(일봉은 595개 전부 있음).
  KIS API가 상장 종목만 주기 때문. 수급 조건으로 과거를 검사하면 결과가 부풀려진다
- **금액 기준은 시대마다 뜻이 다르다** — 시총 5,000억이 2007년엔 상위 10.7%,
  2025년엔 상위 18.0% (전체 시총 1,052조 → 3,987조)

### 재검토 조건

- 오너가 역할 경계를 다시 정의할 때
- 전략군이 눌림매매 외로 확장돼 9단 계층이 안 맞을 때
- 수급 결손을 메워 "당시 기준 종목 목록" 원칙을 수급에도 완전히 적용할 수 있게 될 때

## 미해결 (Open questions)

**없다.** 조건·임계값·진입 방식·검사 구간은 오너가 화면에서 정한다(§0.4) — ADR이 들고 있을 것이 아니다.

안 만든 기능은 PROJECT_GUIDELINES §12, 데이터에 없는 것은 §5.4 에 있다.
