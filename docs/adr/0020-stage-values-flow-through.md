# ADR-0020 — 단계 사이로 값이 흐르게 한다 (검색식 → 진입)

- **상태:** 제안 (오너 승인 대기)
- **날짜:** 2026-08-18
- **관련:** ADR-0009(검색식이 곧 유니버스), ADR-0013(파동 시작점), ADR-0014(지지저항),
  ADR-0019(정체성 v4 · 역할 경계), PROJECT_GUIDELINES §전략 9단 계층

---

## 무엇이 잘못됐나

전략을 9단으로 나눴는데, **단계 사이로 값이 안 흐른다.** 그래서 앞 단계에서 고른 기준이
뒤 단계에서 통째로 무시된다.

```
① 종목 선정   검색식: 250일(52주) 신고가 · 시가총액 상위 N%
                        ↓  아무 값도 안 넘어간다
⑤ 진입        wave_start_of(df, p)      p = 파동(zigzag) 값 + 박스 값뿐
```

`fibonacci.wave_start_of(df, p)` 에 들어가는 `p` 에는 검색식이 한 글자도 없다.
파동 꼭대기는 "파동 바닥 이후 최고 고가"로 **혼자** 정해진다.

### 실측 — 이스트소프트 047560 (2026-08-18)

```
검색식이 고른 이유 : 52주 신고가        →  최근 250거래일 안의 이야기
실제로 그은 파동   : 2023-01-09  8,480  →  49,800  (5.9배, 3년 7개월)
```

2024-01-29 꼭대기(49,800) 뒤로 종가가 그 값을 다시 못 넘어 **3년 7개월째 파동이 안 바뀐다.**
2024-12 에 22,000 → 29,300 (33%, 거래량 10배) 급등이 있었는데도 무시된다 —
상승 전환 판정이 "직전 확정 꺾임 꼭대기를 종가로 넘을 때"뿐이라서다(ADR-0013 6차).

그 결과 되돌림 선이 8,480~49,800 사이에 깔린다. 현재가 8,220 이면 78.6% 선(17,514)보다도
한참 아래라 **어떤 매수 차수도 안 걸린다.**

### 왜 이게 치명적인가

전략 1호는 "**상승 사이클** 눌림매매"다. 그런데 지금은
**검색식이 잡은 사이클과 피보나치가 그리는 사이클이 서로 다른 사이클**이다.
"52주 신고가 찍고 눌린 데서 사면 어떤가"를 확인해야 하는데, 실제로는 3년 반짜리
사이클의 되돌림을 재고 있었다. **성적표의 숫자가 그 질문의 답이 아니다.**

이 시스템의 정체성이 "확인하는 시스템"(ADR-0019)인데, 확인하려던 것과 다른 걸 쟀다.

### 놓을 자리조차 없다

피보나치는 화면에 입력칸이 아예 없다 — `strategyOne.ts` 의
`isFixedDefinition('fib_retrace')` 가 입력칸을 통째로 숨긴다(2026-08-06 "전략 1호 고정 정의").
그래서 이 값을 고칠 입구가 화면에 없다. **오너가 화면에서 고를 수 없는 상태**라
ADR-0019 역할 경계와도 어긋난다.

---

## 무엇은 멀쩡한가 (고치지 않는다)

실측으로 확인했다.

- **시가총액은 기준일 기준이 맞다.** `base` 가 그날 marcap 행이고
  (`walk_forward.py` 의 `by_day[d]`), 순위도 그날 거래되던 종목 안에서만 매긴다
  — 상장 전·상폐 후가 안 섞인다.
- **검색식은 종목 선정에 제대로 걸린다.** 46만 건 대조에서 시총 상위 20% 조건이
  날마다 정상 동작(153,201건).
- **파동 바닥 찾는 것도 쓸 만하다** (오너 2026-08-18: "지금 바닥 구간 잡는 건 얼추 잘하고
  있거든?"). 손대지 않는다.

문제는 **꼭대기(피보나치 끝점)** 하나다.

---

## 결정

### 1. 피보나치 끝점을 고를 수 있게 한다

오너 2026-08-18:

> 피보나치의 끝(최고점)은 내가 설정한 조건 검색값(250일, 52주)에 따라 되어야 하는 것이
> 이 매매전략이야. 근데 애초에 피보나치라는 게 신고가에만 적용하는 게 아니잖아?
> 그냥 특정 형태의 최고점을 찍는 게 피보나치인데, 그러니까 피보나치의 끝점을 52주
> 신고가로 맞추는 옵션을 진입 기법에서 피보나치를 선택했을 때 뜨게 해야 할거야.

피보나치는 신고가 전용 도구가 아니다. 그러니 **못 박지 않고 옵션으로 둔다.**
진입 기법으로 피보나치를 골랐을 때만 화면에 뜬다.

```
피보나치 끝점(최고점)을 어디로 잡을까
  ○ 파동 꼭대기      바닥 이후 최고 고가          (지금 방식, 기본값)
  ○ N일 신고가       최근 N거래일 중 최고 고가
```

**기본값은 지금 방식**이다 — 오너가 고르기 전까지 성적이 안 바뀌어야
"바꿔서 이렇게 달라졌다"를 확인할 수 있다.

### 2. N 은 검색식 값을 그대로 따른다

오너 결정 2026-08-18: "검색식 값을 그대로 따른다."

검색식에 `new_high` 또는 `new_high_burst` 가 있으면 그 `days` 를 그대로 쓴다.
검색식을 250 → 120 으로 바꾸면 피보나치 끝점도 같이 120일 자로 바뀐다.
**둘이 어긋날 길이 없다.** 화면에는 따라온 값을 흐린 글씨로 보여 준다
(어디서 온 값인지 안 보이면 또 두 갈래가 된다).

검색식에 신고가 조건이 없는데 `N일 신고가` 를 고르면 오류다 — 조용히 기본값을 쓰지 않는다.

### 3. 값이 흐르는 길을 하나로 만든다

오너 결정 2026-08-18: "단계 사이 값 전달을 통으로 고친다."

지금은 ③ 시뮬레이션·④ 백테스트가 각자 요청 본문을 조립하고, 진입 단계는 그중
파동 값만 받는다. 앞으로는 **단계 값을 한 덩어리로 묶어 뒤 단계에 넘긴다.**

```
StageContext = {
  selection: { conditions, logic, new_high_days | None },   ← ①이 채운다
  entry:     { key, params },                               ← ⑤가 읽는다
  ...
}
```

- 뒤 단계는 앞 단계 값을 **읽기만** 한다. 고쳐 쓰지 않는다.
- 앞 단계가 안 정한 값을 뒤 단계가 지어내지 않는다 — 없으면 오류로 알린다.
- 계약은 한 곳(`layer3_strategy` 카탈로그)에만 둔다. 화면이 다시 정의하지 않는다
  (CLAUDE.md: "화면에서 고를 수 있는 것을 파이썬에 다시 정의하지 않는다").

---

## 검증

바꾸기 전후로 **전 구간 백테스트를 돌려 숫자로 대조한다.**

- 기본값(파동 꼭대기)으로 돌리면 지금과 성적이 **완전히 같아야** 한다. 다르면 버그다.
- `N일 신고가` 로 돌린 성적을 따로 낸다 — 승률·기대값·거래 수·미체결 수.
- 이스트소프트 047560 · CMG제약 058820 은 눈으로도 확인한다(오너가 짚은 종목).

## 남은 문제 (이 ADR 범위 밖)

- **매수 목표가가 손절선 아래로 내려가는 경우.** CMG제약 058820 2020-07-24 실측:
  38.2% 되돌림 4,788 원이 지지저항 라운드 가격 4,300 원으로 끌려가 손절선 4,310 원
  아래가 됐다. 체결되는 순간 손절 조건이 성립해 **같은 날 사고 같은 날 손절**된다.
  지지저항 스냅이 되돌림 선의 순서를 뒤집을 수 있다는 뜻이다. 별도 결정 필요.
- **라운드를 완전히 분리할지.** 지금은 규칙 2·3(같은 파동 재매매 금지, 매매 중 새 시작
  금지)으로 라운드가 묶여 있다. 파동이 제대로 갱신되면 이 의문 자체가 줄어들 수 있어,
  끝점 옵션을 넣은 뒤 다시 본다.
