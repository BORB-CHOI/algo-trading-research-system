# ADR-0015: ④ 백테스팅 — 전략 1호 전수 검사 v1

- **상태:** 수락 (구현 완료 — `layer4_execution/strategy_one.py` / `POST /api/backtest` / ④ 탭)
- **날짜:** 2026-08-06
- **관련:** ADR-0007(백테스트 골격), ADR-0013·0014(전략 1호 정의), ADR-0004(거래비용)

## 맥락 (Context)

오너: "종목 선정은 시뮬레이션 때 의미가 없어야 해. 4번째로 백테스팅 탭 만들어서 거기서
실질적으로 전수 검사 들어가야 하는 거라." ③은 대표 종목 하나로 전략 동작을 눈으로
확인하는 자리, ④가 검색식 유니버스 전 종목에 실제 성과를 재는 자리다.

## 결정 (Decision)

`run_strategy_one` — ADR-0007 골격(`_select_universe`·`slice_split`·`Trade`·`_aggregate`·
`CostModel`)을 재사용하고, 신호 기반 엔진 대신 전략 1호의 지정가 방식 라운드를 돈다.

- **시간 구조**: 유니버스·기준일 = split 시작 직전 거래일 1회 선별(v1 관례). 세팅
  (사이클·지지저항·목표가·손절)은 기준일 **왼쪽만**, 체결 스캔은 기준일 다음 거래일부터
  split 끝까지 **오른쪽만** — "신호 계산 시점 < 체결 시점"이 구조로 강제된다.
- **체결 규칙 = ③ 시뮬레이션과 동일**: 매수 Low≤목표가 첫 날, 매도는 마지막 매수 체결
  이후 High≥목표가, 손절은 첫 매수 체결일부터(발동 시 이후 매도 취소 — 보수).
- **비용**: 왕복 정액률(ADR-0004 placeholder) 포함. 지정가라 슬리피지 v1 미적용 —
  시장가 추격이 없고 체결 보수성("그 가격까지 와야 체결")이 이미 반영.
- **평가**: 잔여 비중은 구간 마지막 가용 종가(상폐면 끊긴 시점 종가 — 보수).
  종목당 라운드 1회 → Trade 1건(비중가중 평단→청산가). 집계는 runner._aggregate
  (승률·기대값·순차 복리 누적·**N<30 reliable=False**).
- **§4.1 가드**: Test split 은 UI 명시 체크(`i_know_test_is_once`) 없이는 서버가 거부.
- ④ 탭 입력 = ①의 검색식 + ②의 현재 전략 값 + split. 정량 값 하드코딩 없음(ADR-0009).

## 결과 (Consequences)

- 실측(검증 구간 2024, "신고가+거래대금(250일/1000억/5일)" 유니버스 23종목, -45%/10일/1%,
  38.2/50/61.8 3분할): 거래 12건 · 승률 41.7% · 평균 +18.7% · 누적(순차 복리) -14.9%,
  응답 2.3초. **평균이 +인데 누적이 -인 것**이 순차 복리(자본 배분 무시) 한계의 실례다.
- 파라미터 튜닝은 Train/Validate 에서만 — 이 탭이 곧 "고점·저점 기준·같은 선 폭·하락
  기준을 감이 아니라 데이터로 정하는" 자리다.

## v1 한계 (알려진 것, ADR-0007 개정에서 다룰 것)

1. 선별 1회(기준일 고정) — 구간 중 신규 진입/이탈 미반영(point-in-time 재선별 후속).
2. 종목당 라운드 1회 — 반복 매매(매도 후 재매수) 루프 없음.
3. 누적 수익률 = 순차 복리 — 자본 배분·동시 보유 미반영(포트폴리오 자본곡선 후속).
4. 추세선(대각) 지지저항 미지원(BORB-64).
