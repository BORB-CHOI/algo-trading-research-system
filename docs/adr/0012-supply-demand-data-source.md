# ADR-0012: 수급 데이터 소스 — KIS 종목별 투자자매매동향(일별)

- **상태:** 제안
- **날짜:** 2026-08-05
- **관련:** ADR-0002(데이터 소스), ADR-0010(KIS 어댑터), BORB-33/34/35/36

## 맥락 (Context)

외국인·기관·개인이 각 종목을 하루에 얼마나 순매수했는지는 **계산으로 만들 수 없다.**
거래소가 집계해서 내려주는 정보다. marcap 에는 없고, OHLCV 로 유도할 방법도 없다.
ADR-0002 는 이 항목만 "소스 미정"으로 남겨뒀다.

Layer 2 신호를 붙이려면 결국 이 데이터가 필요하다. 그래서 후보 세 갈래를 실측으로 갈랐다.

## 검토한 선택지 (Options)

### 1. KIS `종목별 투자자매매동향(일별)` — TR `FHPTJ04160001`

`scripts/kis_probe_supply.py supply` 로 실전 키를 써서 직접 찔러본 결과다(2026-08-05).

| 확인한 것 | 결과 |
|---|---|
| 과거 이력 | 요청일 `20170102` 에 `20161121~20170102` 응답 — **백테스트 구간 2017~ 을 덮는다** |
| 한 호출 분량 | **30 거래일 고정** |
| 투자자 구분 | 외국인(등록·미등록 분리)·개인·기관 합계 + 증권/투신/사모/은행/보험/종금/기금/기타법인 |
| 단위 | 순매수 **수량**(`*_ntby_qty`)과 **금액**(`*_ntby_tr_pbmn`) 양쪽 |
| 가격 동봉 | 시·고·저·종가와 누적 거래량/거래대금이 같은 행에 온다 |

방법론 가드레일에 걸리는 게 없다. 날짜를 지정해 부르는 API 라 **point-in-time 재현이 된다.**
ADR-0010 의 조회상위(`hts-top-view`)가 "지금 이 순간"만 줘서 백테스트에 못 쓰던 것과 정반대다.

한계는 **호출 제한**이다. 프로브를 연달아 돌리자 바로 `EGW00201 초당 거래건수를 초과하였습니다`
가 떨어졌다. 백필은 스로틀 없이는 성립하지 않는다.

### 2. 키움 REST API — `ka10008 주식외국인종목별매매동향`

종목별 수급 엔드포인트가 있기는 하다. 다만 **앱키를 따로 발급받아야 하고**, 주문 창구를
KIS 로 확정한 마당에(CLAUDE.md) 조회만 하러 증권사를 하나 더 붙이는 셈이다.
과거 이력 한도는 확인하지 않았다 — 1번이 이미 필요한 구간을 덮어서 확인할 이유가 없었다.

### 3. 통째로 받을 수 있는 공개 데이터셋

찾지 못했다. marcap 처럼 parquet 으로 통째 올라온 종목별 수급 저장소는 없다.

- `pykrx` 는 항목 구성이 우리가 원하는 그대로지만 KRX 웹 스크래핑이고,
  CLAUDE.md 가 로그인 게이트 때문에 **신규 의존 금지**로 못 박아둔 라이브러리다.
- KRX Data Marketplace(`MDCSTAT023 투자자별 거래실적(개별종목)`)는 화면 조회 기반이다.
  대량 백필 용도로 쓰려면 결국 같은 스크래핑 문제로 돌아온다.

## 결정 (Decision)

**KIS `FHPTJ04160001` 을 수급 데이터의 정본 소스로 채택한다.** 키움은 예비로만 남긴다.

수집 방식:

- 종목 하나당 날짜를 30 거래일씩 뒤로 밀며 연속 수집한다.
- 스로틀은 **필수**다. 초당 호출 수는 placeholder — 실측으로 잡는다.
- 저장은 `data/derived/supply/` 아래 종목별 parquet. marcap 원본은 건드리지 않는다.
- 수집 시각과 요청 파라미터를 같이 적어, 나중에 어느 시점에 받은 값인지 되짚을 수 있게 한다.

정량값(스로틀 간격·재시도 횟수·백오프)은 전부 placeholder다. 하드코딩하지 않는다.

## 결과 (Consequences)

**백필 비용이 이 결정의 진짜 값이다.** 2017-01~현재는 약 2,350 거래일이고,
한 호출이 30 거래일이니 **종목당 약 79 호출**이다.

| 범위 | 호출 수 | 초당 2건 기준 소요 |
|---|---|---|
| 전 종목 (약 2,800) | 약 22만 | 약 30시간 |
| 거래대금 상위 500 | 약 4만 | 약 5시간 |
| 거래대금 상위 200 | 약 1.6만 | 약 2시간 |

한 번 받아두면 증분만 갱신하면 되므로 반복 비용은 아니다. 다만 **어디까지 받을지는
유니버스 결정과 묶여 있다.** 상위 N 만 받으면 그 순간 백테스트 유니버스도 상위 N 으로
잘린다 — 살아남은 것만 보는 착시(survivorship bias)와는 다른 종류지만, 유니버스를
사후에 좁히는 것이라 결과가 부풀 수 있다. **상장 시점 기준으로 자르지 않도록 주의한다.**

후속 작업:

1. KIS 클라이언트에 스로틀·재시도·백오프 (ADR-0010 미해결 4번과 같은 작업)
2. 백필 스크립트 + 증분 갱신 (`scripts/backfill_dart.py` 와 같은 결)
3. 데이터 스키마 확정 — `DATA_SCHEMA` 에 수급 섹션 추가
4. 수집 후 검증: 거래정지일 처리, 결측 구간, marcap 거래량과의 정합

재검토 조건: KIS 가 이 TR 의 이력 제공 범위를 줄이거나, 호출 제한이 백필을 불가능하게
만들면 키움(2번)으로 되돌아간다.

## 미해결 (Open questions)

1. **어느 범위까지 백필할 것인가.** 전 종목 30시간이냐, 상위 N 종목 몇 시간이냐.
   오너 결정이 필요하다. 시간보다 중요한 건 유니버스가 여기서 굳어진다는 점이다.
2. **상장폐지 종목은 이 API 로 조회되는가.** 확인하지 않았다. 안 되면 상폐 종목의 수급이
   비고, CLAUDE.md 가 금지한 생존 편향이 수급 신호에만 생긴다. **백필 전에 반드시 확인한다.**
3. 등록 외국인(`frgn_reg_ntby_qty`)과 미등록(`frgn_nreg_ntby_qty`)을 나눠 쓸지, 합계만 쓸지.
4. 기관 세부 8종(증권·투신·사모·은행·보험·종금·기금·기타법인) 중 신호로 쓸 것을 고르는 일은
   Layer 2 몫이다. 데이터는 일단 다 받아둔다.
