## 1. 왜 지금 바꾸는가

v3.8은 세 가지를 사실로 전제했는데, 셋 다 검증된 적이 없다.

1. **"AI와 조건 라이브러리를 쌓으면 시스템이 영원히 진화한다."**
   → 실제로 하고 있는 일은 진화가 아니라 **가설 검증**이다. 진화의 현실적 형태는
   "이 전략의 힘이 약해졌으니 새 가설을 연구할 때"라고 알려 주는 것뿐이다.
2. **"4요소(기술적 통계 + 재료 해석 + 시장 심리 + AI 판단)를 결합하면 손익비가 비대칭이 된다."**
   → 이건 시스템의 존재 이유가 아니라 **검증할 가설 중 하나**다. 'AI 판단'은 아예 요소에서 빠진다.
3. **"고수의 중요도 순위(시황 > 투자심리 > 주도주 > …)를 시스템 가중치에 반영한다."**
   → 순위 자체가 가설이다. 무엇이 미래 수익과 관계있는지는 데이터가 정한다.

지침서 4,134줄을 미션 문서와 대조한 결과 **정면 충돌 183곳**이 나왔고, §7(영원한 진화)·
§10~13·§3.1~3.8에 몰려 있다.

## 2. 새 정체성 (문서 첫 문장이 될 것)

> **ATS는 검증된 트레이더(실전 10년+, 큰 자금 운용)의 매매 관점과 발언을 하나하나 검증할
> 가설로 바꾸고, 한국 증시 과거 데이터로 실제 미래 수익과 관계가 있는지 확인한다.
> 시장 상황·종목 상태·매매 유형별로 통하는 전략을 찾고, 사용자가 최종 승인한 매매 계획만
> 예약 매수·매도 주문으로 자동 실행하며, 그 전략의 힘이 약해지는지 감시하는
> 알고리즘 매매·연구 시스템이다.**

역할 분리 (타협 불가):

| 누가 | 무엇을 |
|---|---|
| **사람** | 무엇을 검증할지 결정 · 고수 발언 해석 · 가설 정의 · 전략군 결정 · **최종 승인** |
| **AI** | 가설을 숫자로 바꾸는 보조 · 실험 코드 작성 보조 · 통계 요약 · 실패 조건 탐색 · 알파 약화 탐지 |
| **시스템** | 데이터 처리 · 종목 선별 · 백테스트 · 체결 시뮬레이션 · **승인 후** 예약 주문 실행 · 성과 기록 |

**AI가 BUY/SELL·비중·손절선을 정하지 않는다.** (CLAUDE.md MCP 규칙과 동일)

### 2.1 역할 경계 — 이 문서에서 가장 자주 어겨지는 부분 (오너 지적 2026-08-16)

> "너는 그냥 코딩, (뉴스나 재료 수집해야 할 타이밍 됐을 때) 자연어로 해석 용도고,
> 내가 필요하면 준비된 데이터에 따라 검증 계산 돌리면 되는 거야.
> 나머지는 내가 웹에서 조작하면서 알아서 한다고."

**AI(클로드)가 하는 일 — 이 셋뿐이다.**

1. **코딩.** 오너가 화면에서 고를 수 있게 도구를 만든다.
2. **글 해석.** 뉴스·재료를 수집할 때가 되면 자연어를 숫자로 바꾼다.
3. **시키면 계산.** 오너가 요청하면 준비된 데이터로 검증 계산을 돌리고 결과를 보고한다.

**AI가 하지 않는 일:**

- 어떤 조건으로 종목을 거를지 **정하지 않는다** — 오너가 화면에서 고른다 (ADR-0009)
- 어떤 가설을 먼저 검증할지 **우선순위를 매기지 않는다**
- 검증 실험 목록을 **설계하지 않는다**
- 임계값(시총 하한·되돌림 비율·호가 오프셋)을 **고르지 않는다**
- 백테스트 구간을 **정하지 않는다**

**AI의 일은 "오너가 그걸 화면에서 고를 수 있게 만드는 것"이다.**
화면에 선택지가 없으면 그건 AI가 만들 것이고, 선택지가 있으면 고르는 건 오너다.

⚠️ 이 설계서 초안(2026-08-16 오전)이 이 경계를 어겼다. "실험 A~G를 비교한다",
"가설 카드에 우선순위를 매긴다", "선정 규칙을 파이썬에 정의한다"는 전부 오너의 일을
AI가 가져간 것이다. 아래 §5·§7은 그 지적을 받아 고쳐 쓴 것이다.

## 3. 전략 9단 계층 (v4.0 뼈대)

```
종목 선정 (Selection)        어떤 종목을 볼 것인가
   ↓
시장 상황 (Market Regime)    오름장·횡보장·내림장 중 어디인가
   ↓
전략군 (Strategy Family)     눌림 / 돌파 / 박스탈출 / 갭 / 급등주 …
   ↓
모양 (Setup)                 어떤 형태가 만들어졌는가
   ↓
진입 모델 (Entry Model)      어느 가격·조건에서 들어갈 것인가
   ↓
비중 (Position Sizing)       얼마를 살 것인가
   ↓
청산 모델 (Exit Model)       어디서 얼마를 팔 것인가
   ↓
위험 관리 (Risk Model)       손절 · 최대 비중 · 동시 보유 수
   ↓
실행 (Execution)             실제 주문을 어떻게 낼 것인가
```

**지금 만들어 둔 전략 1호가 이 계층에서 차지하는 자리:**

| 계층 | 지금 코드 | v4.0 이름 |
|---|---|---|
| 전략군 | — | 상승 사이클 눌림매매 |
| 모양 | [market_structure.py](../../../src/layer3_strategy/market_structure.py) · [zigzag.py](../../../src/layer3_strategy/zigzag.py) · [surge.py](../../../src/layer3_strategy/surge.py) | 상승 사이클 이후 눌림 |
| 진입 모델 | [fibonacci.py](../../../src/layer3_strategy/fibonacci.py) · [entry_levels.py](../../../src/layer3_strategy/entry_levels.py) · [fib_zone.py](../../../src/layer3_strategy/fib_zone.py) | **피보나치 되돌림 진입 모델** |
| 청산 모델 | [support_resistance.py](../../../src/layer3_strategy/support_resistance.py) · [fills.py](../../../src/layer4_execution/fills.py) · [stops.py](../../../src/layer4_execution/stops.py) | 지지/저항 존 분할 청산 |
| 실행 | [strategy_one.py](../../../src/layer4_execution/strategy_one.py) · [walk_forward.py](../../../src/layer4_execution/walk_forward.py) | 백테스트 실행 하네스 |

즉 "전략 1호 = 피보나치"가 아니라, **"상승 사이클 눌림매매"라는 전략군의 진입 모델 하나가
피보나치**다. 같은 전략군에 "전고점 지지 진입", "이동평균 진입", "거래대금 기반 진입"을
나중에 형제로 끼워 넣을 수 있게 자리를 만드는 것이 이 재정의의 목적이다.

**격하가 아니라 승격이다. 코드는 한 줄도 지우지 않는다.**

## 4. 핵심 원칙 — "그때 알 수 있었던 정보만"

v3.8은 "point-in-time universe"라는 학술 용어로 **종목 목록에만** 이 원칙을 걸었다.
v4.0에서는 **모든 값**에 건다.

> 모든 값은 이 질문을 통과해야 한다: **"이 값을 계산할 당시 실제로 알 수 있었는가?"**

| 항목 | ⭕ | ❌ |
|---|---|---|
| 가격 | 그날까지의 가격 | 다음 날 가격으로 오늘 신호 수정 |
| 시가총액 | 그날 시총 | 오늘 시총으로 과거 종목 선별 |
| 수급 | 그날 공개분 | 미래 수급 누적해 "과거 강한 수급" 정의 |
| 뉴스·재료 | 그날까지 공개분 | 나중에 밝혀진 사실 반영 |
| 주도주 | 그날까지의 성과·거래대금·테마로 판단 | 몇 달 뒤 성과 보고 "그때 주도주였다" |
| 52주 신고가 | 그날까지의 52주 | 미래 신고가 알고 후보 지정 |

### 5.2 가설 항목 서식 — **원재료 목록이지 검증 계획이 아니다**

이 폴더는 **오너가 화면에서 조건을 만들 때 꺼내 쓰는 재료 목록**이다.
AI가 우선순위를 매기거나 검증 순서를 정하지 않는다 (§2.1).

```markdown
### 52주 신고가 근접

- **출처 발언:** (고수 영상 / 오너 발언 / 학술) — 원문 그대로
- **쉬운 말:** 1년 최고가 가까이 있는 종목
- **전략 계층:** 종목 선정
- **필요 데이터:** 일봉 (있음 ⭕)
- **화면에서 고를 수 있나:** ⭕ 조건검색 「신고가」 항목
- **주의:** 그날까지의 52주만 본다 — 미래 신고가를 알고 후보를 지정하면 안 된다
```

넣지 않는 항목: 우선순위, 검증 상태, 실험 번호(H-NNN), 실험 조합표(A~G).
전부 오너가 화면에서 정하는 것이다. **초안에 있던 이 항목들은 철회한다.**

## 6. 백테스트 실측 점검 결과 (오너 질문: "지금 백테스팅 문제 없는 거 맞아?")

**실제로 돌리고 코드를 뜯어본 결과다. 자동 yes 아님.**

### 6.1 튼튼한 것 ⭕

- **테스트 618개 전부 통과** (2026-08-16 실측, 실패 0)
- **미래 훔쳐보기 방지가 구조로 강제된다.**
  계획은 `df["Date"] <= base_date`, 체결은 `searchsorted(base_date, side="right")` —
  기준일 **다음 날부터**만 본다 ([strategy_one.py:137-144](../../../src/layer4_execution/strategy_one.py))
- **파동 계산이 인과적이다.** `wave_series`의 각 행이 그날까지만 본다.
  게다가 **"하루씩 굴린 값 == 그날까지 잘라 다시 계산한 값"** 동치 테스트가 있다
  ([test_market_structure.py:124](../../../tests/test_market_structure.py)) — 이게 look-ahead 방지의
  가장 강한 형태다. 추가로 `test_미래를_안_본다`, AVWAP look-ahead 회귀 테스트도 있다.
- **살아남은 것만 보는 착시가 없다.** `data/derived/adjusted` 5,478종목 — 현재 상장은 약 2,600.
  망한 회사가 자기 시절 행에 그대로 남아 있다.
- **거래비용 왕복 정액률 적용** (ADR-0004)
- **Test 구간 1회 가드가 있다.** `slice_split`이 `i_know_test_is_once` 없이는 거부한다.

### 6.2 실제 구멍 ⚠️ — 3건

**① 구간 강제가 실제 쓰임새와 안 맞는다. (오너 결정으로 해소)**

`backtest.py`의 `SPLITS`가 연습/검증/시험을 2020~2025로 못박고 있는데, 데이터는
**1995년부터** 있다. 「전 구간」 검사(`/api/backtest/all`)는 이 구간을 아예 안 쓰고
`start`/`end`를 직접 받는다 — 즉 화면에서 날짜를 고르는 길과 코드가 못박은 구간이 따로 논다.

**오너 결정 (2026-08-16): 나누지 않고 2007년부터 전체로 돌린다.**
구간을 어떻게 쓸지는 오너가 화면에서 정한다. 코드가 구간을 강제하지 않는다.

처리: `SPLITS` 강제를 없애고 **화면에서 고른 날짜가 그대로 검사 구간**이 되게 한다.
기본값만 `2007-01-01 ~ 최신 거래일`로 둔다.

**② 지정가 체결 가정이 낙관적이다. (중간)**

매수 = `Low ≤ 목표가`면 체결로 친다. 실제로는 그 가격에 **닿기만** 하고 내 주문 앞
물량이 안 빠지면 체결이 안 된다. 코드 주석도 "슬리피지 v1 미적용"이라고 인정한다
([strategy_one.py:28](../../../src/layer4_execution/strategy_one.py)) — `slippage.py`는 있지만 이 경로에선 안 걸린다.
미션 문서 §19-2(체결 가능성 기록)가 정확히 이 자리다.

처리: 미체결·부분체결·유동성 부족을 **기록**부터 시작한다. 체결 규칙 변경은 별도 ADR.

**③ "돈 무한" 전제 — 계좌 수익률이 아니다. (의도된 것, 다만 읽는 법 주의)**

동시 보유 종목 수·비중 배분을 안 따진다. 승률·종목당 수익률은 맞지만
**계좌 수익률로 읽으면 안 된다.** 코드에 이미 명시돼 있다 ([walk_forward.py:19](../../../src/layer4_execution/walk_forward.py)).
포트폴리오 자본곡선은 BORB-66에 남아 있다.

### 6.3 데이터 실측 — 지침서 서술이 틀렸다 (2026-08-16 확인)

| 데이터 | 실제 범위 | 확인 방법 |
|---|---|---|
| 가격·시가총액 (marcap) | **1995 ~ 2026, 빠진 해 0** | `data/marcap/data/marcap-*.parquet` 32개 |
| 수정주가 일봉 | **5,478종목, 1995~** | `data/derived/adjusted/` |
| 수급 (외인/기관/개인) | 2,473종목 | `data/derived/supply/` |

**지침서·CLAUDE.md의 "데이터 2017-01~현재"는 틀린 서술이다.** v4.0에서 고친다.
2007년은 물론 IMF 외환위기(1997)까지 있다. 2007년 실측: 246거래일 · 1,967종목.

**⚠️ 수급 데이터에 망한 회사가 통째로 빠져 있다.**

```
2010년엔 있었고 2025년엔 없는 종목(상폐 등) : 595개
  └ 그중 일봉이 있는 것 : 595 / 595  ⭕
  └ 그중 수급이 있는 것 :   0 / 595  ❌
```

KIS API가 상장 종목만 주기 때문이다. 수급 조건을 넣고 과거를 검사하면 **망한 회사가
애초에 표본에서 빠져** 결과가 부풀려진다 — CLAUDE.md가 금지한 "살아남은 것만 보는 착시"다.

**처리: 고치지 않고 알린다.** 오너가 화면에서 수급 조건을 고르면 "이 조건을 쓰면 상폐
종목이 빠집니다"를 표시한다. 다른 데서 받아올지, 최근 구간에서만 쓸지는 **오너가 정한다.**

**⚠️ 금액 기준은 시대마다 뜻이 다르다** (실측):

| 연도 | 전체 시총 | 시총 5,000억 = 상위 몇 % |
|---|---|---|
| 2007 | 1,052조 | 상위 **10.7%** |
| 2015 | 1,448조 | 상위 15.3% |
| 2025 | 3,987조 | 상위 **18.0%** |

그래서 **화면에 순위 기준 선택지를 추가**한다(§7-1). 금액으로 걸지 순위로 걸지는
**오너가 화면에서 고른다.** 통화량(M2)·유동성 보정은 오너 지시로 지금은 하지 않는다.

### 6.4 미션 문서가 코드와 어긋난 곳 (자동으로 안 고치고 보고)

- **미션 §17 "날짜별 재선별이 아직 안 됐다" → 이미 됐다.**
  [walk_forward.py](../../../src/layer4_execution/walk_forward.py)가 2026-08-10에 정확히 그 문제를 고쳤다
  (거래일마다 검색식 재실행, 47분→2.7분, 1,616거래일×3,323종목 실측). 미션 문서가 본 건 옛 `strategy_one` 쪽이다.
  → v4.0에서는 "1순위 과제"가 아니라 **"이미 있는 자산"**으로 적는다.
- **미션 §15 "시총 5,000억+52주 신고가 하드코딩 여부 확인 안 됨" → 하드코딩 아님.**
  조건검색식이 전부 데이터로 주입된다(ADR-0009). 결론(가설로 취급)은 맞지만 근거가 다르다.
