## §0. 이 시스템은 무엇인가

### 0.1 한 문단

> **검증된 트레이더(실전 10년+, 큰 자금 운용)의 매매 관점과 발언을 하나하나 확인할 수 있는
> 주장으로 바꾸고, 한국 증시 과거 데이터로 그게 실제 미래 수익과 관계가 있는지 확인한다.
> 시장 상황·종목 상태·매매 유형별로 통하는 전략을 찾고, 사용자가 최종 승인한 매매 계획만
> 예약 매수·매도 주문으로 자동 실행하며, 그 전략의 힘이 약해지는지 지켜보는
> 알고리즘 매매·연구 시스템이다.**

### 0.2 아닌 것

- ❌ AI가 알아서 사고파는 완전 자율 자동매매
- ❌ AI가 끝없이 새 전략을 만들어내는 시스템
- ❌ 증시 전체에 통하는 만능 전략 하나를 찾는 일

### 0.3 맞는 것

- ⭕ 확인된 규칙으로 시스템이 **후보와 주문 계획**을 만들고, **사람이 최종 승인**하는 구조
- ⭕ 승인된 계획의 예약 매수·매도·분할 주문 **실행을 자동화**
- ⭕ 전략의 힘이 약해지면 **"새 연구가 필요하다"고 알려 주는** 것

판단 이전의 연구와 판단 이후의 실행을 자동화한다. **판단 자체는 사람이 한다.**

### 0.4 누가 무엇을 하나 (타협 불가)

| 누가 | 무엇을 |
|---|---|
| **사람 (오너)** | 무엇을 확인할지 결정 · 고수 발언 해석 · 조건과 임계값 선택 · 전략군 결정 · 검사 구간 결정 · **최종 승인** |
| **AI (클로드)** | **코딩** · (뉴스·재료 수집 시점의) **글 해석** · **시키면 계산 돌리고 결과 보고** |
| **시스템** | 데이터 처리 · 종목 선별 · 백테스트 · 체결 흉내 · 성과 기록 · **승인 후** 예약 주문 실행 |

**AI가 하지 않는 일:**

- 어떤 조건으로 종목을 거를지 **정하지 않는다** — 오너가 화면에서 고른다 ([ADR-0009](../adr/0009-strategy-as-data.md))
- 무엇을 먼저 확인할지 **우선순위를 매기지 않는다**
- 임계값(시총 하한·되돌림 비율·호가 오프셋)을 **고르지 않는다**
- 백테스트 구간을 **정하지 않는다**
- BUY/SELL·비중·손절선을 **정하지 않는다** (CLAUDE.md MCP 규칙과 동일)

**AI의 일은 "오너가 그걸 화면에서 고를 수 있게 만드는 것"이다.**
화면에 선택지가 없으면 그건 AI가 만들 것이고, 선택지가 있으면 고르는 건 오너다.

      ↓

      ↓
[6] 전략군 고르기 (눌림 / 돌파 / 박스탈출 / 갭 …)
      ↓

      ↓

      ↓

### 0.6 숫자 표기 원칙

**이 문서와 `../research/hypotheses/`의 모든 숫자(임계값·비율·기간)는 임시값이다.**

- 고수 휴리스틱 + 직관 + 학술 통설로 추정한 값
- 실제 값은 **데이터로 확인한 뒤 교체**
- 지금 시점에 그 숫자가 *"정확한가"* 는 확인 대상 ❌
- 지금 시점에 *"구조가 말이 되는가, 무엇을 재야 하는가"* 가 확인 대상 ⭕

숫자를 바꾸는 것은 *"기준 흔들기"* 가 아니라 *"임시값 교체"* 다.
**구조를 바꾸는 것만 기준 변경**이고, 그건 신중히 한다.

### 0.7 마감 없음

이건 프로젝트가 아니라 시스템이다.

- ❌ 6주 마감, 8주 마감 같은 기한
- ❌ "완성" 이라는 상태
- ⭕ 발언 → 확인할 주장 목록에 추가 → 같은 방식으로 확인 → 통과한 것만 전략 후보로
- ⭕ 전략의 힘이 약해지는지 계속 지켜보고, 약해지면 새 연구가 필요하다고 알림

기한 압박이 정직한 확인을 갉아먹는 걸 막기 위한 결정이다.

### 0.8 매매 스타일

**스윙만. 단타 ❌.** (오너 결정)

- 보유 기간: 며칠 ~ 몇 주
- 장중 의도적 무개입 (→ §8.1)
- 장기투자 ❌ (회전율 부족)
- 진입 방식은 전략별로 확인 후 정한다 — **종가 매수 전제(구 ADR-0001)는 폐기**

## §1. 오너 프로필

- **목표:** 최종 목표는 실거래 수익. 다만 거기까지 가는 길에 확인 작업은 필수다.
  확인 없는 실거래는 하지 않는다
- **자본:** 1,000만원 이내. 단계적 투입 (100 → 300 → 1000만)
- **시장:** 한국 주식 (KOSPI/KOSDAQ). 미국은 1년+ 후 선택지
- **매매 스타일:** 스윙 (며칠~몇 주)
- **상황:** 대학생. 시스템 빌더 지향, 장중 의도적 무개입
- **프로그래밍:** 가능
- **종목 직관:** 없음 · **메타 직관:** 있음 (기술적·시황·재료·재무·심리 결합 방향성)
- **관찰:** 실전 10년+ 트레이더를 6년간 관찰 (계좌 인증 기록 있음, 시드 수십억대)

### 1.1 직관 프로파일의 뜻

종목 직관 없음 + 메타 직관 있음 = **시스템 빌더에 맞는 형태다.**

- 본인이 시스템을 실제로 따를 수 있다 (펀드매니저형은 못 따른다)
- 시스템 결정에 감정 개입이 적다

종목 선별은 확인된 규칙(코드)이 하고, 최종 판단은 본인이 승인한다.
LLM은 뉴스·재료 같은 글을 숫자로 바꾸는 보조까지만 한다.

### 1.2 참고하는 하루 (실전 10년+ 트레이더의 운영 방식)

```
새벽:     시황·관심 테마 분석 (장 시작 전 시나리오)
9시 전:   예약 매수·예약 매도 주문 세팅
9~15:30:  장중 무개입 (의도적으로 안 봄)
저녁:     오늘 회고 + 내일 시나리오 미리보기
주말:     큰 사건 없으면 안 함 ("대응 못 하는데 신경 안 씀")
```

이 흐름을 **시스템(확인된 규칙 코드 + 승인 후 예약 주문)으로** 자동화한다.
LLM은 새벽 시황·재료 해석 같은 글 정량화 보조만 한다. → §8

### 1.3 처음 가동할 때 부족한 것

LLM이 못 가진 것 (이게 AI에게 전략 창조를 맡기지 않는 근거다):

- 한국 시장 특수성 (외인/기관 일별 수급의 의미)
- 테마주 매매의 미시 동학 (대장주 회전, 점상 패턴)
- 재료 해석 깊이
- 위치 × 시점 × 강도 매트릭스

**채우는 방법:** 트레이더 발언을 출발점 주장으로 삼고, 데이터로 확인해 갱신한다.
발언은 **어디서 시작할지**를 알려줄 뿐, **채택 여부는 데이터가 정한다.**

### 1.4 살아남는 것이 먼저

> *"오래 살아남아야 이런 것들을 다 볼 수 있다."*
> *"시간 자녀라는 표현이 내가 좋아하는 말이에요."*

가장 중요한 것은 *수익률 극대화*가 아니라 **계좌가 살아남는 것**이다.

1. **매매 안 하면 죽지 않는다.** 안 사면 예수금은 그대로다.
   굶주린 채로 생고기 먹으면 배탈 난다 — 조급한 매매가 손절을 부른다.
   시장 사이클은 한 달 ~ 분기 단위다. 못 참고 매매하면 손실이다
2. **미수·신용·스탁론 금지.** 깡통 위험이 무한대다.
   한국 시장 일별 변동성에 빚을 얹으면 자살이다
3. **분기당 한두 달은 시장이 나쁘다고 가정한다.**
4. **거래를 많이 한다고 수익이 늘지 않는다** (Barber & Odean 2000 — 거래 빈도 상위 20%는
   하위 20%보다 **연 7%p 낮은 수익**)

## §2. 왜 한국 시장인가

| 항목 | 한국 | 미국 |
|---|---|---|
| 외인/기관 **일별 수급 공개** | ⭕ | ❌ |
| 한국어 뉴스 NLP | 경쟁 적음 | 포화 |
| 알파 부패 속도 | 느림 (Jacobs & Müller 2020) | 빠름 |
| 세금·수수료 | 유리 | 불리 (양도세) |

**일별 수급 공개가 이 프로젝트의 가장 큰 무기다.** 미국엔 없다.

미국 장기 ETF 같은 건 **별도 계좌**로 한다 — 두 활동을 한 시스템에 섞지 않는다.

## §3. 전략은 아홉 칸으로 정의한다

```
종목 선정 (Selection)      어떤 종목을 볼 것인가        → ../research/hypotheses/selection.md
   ↓
시장 상황 (Market Regime)  오름장·횡보장·내림장          → ../research/hypotheses/regime.md
   ↓
전략군 (Strategy Family)   눌림 / 돌파 / 박스탈출 / 갭 …
   ↓
모양 (Setup)               어떤 형태가 만들어졌는가       → ../research/hypotheses/entry.md
   ↓
진입 (Entry Model)         어느 가격·조건에서 사는가      → ../research/hypotheses/entry.md
   ↓
비중 (Position Sizing)     얼마를 살 것인가              → ../research/hypotheses/exit.md
   ↓
청산 (Exit Model)          어디서 얼마를 파는가          → ../research/hypotheses/exit.md
   ↓
위험 관리 (Risk Model)     손절 · 최대 비중 · 동시 보유 수 → §7
   ↓
실행 (Execution)           실제 주문을 어떻게 내는가      → §6
```

**하나의 전략 = 이 아홉 칸을 다 채운 것.**

### 3.1 지금 만들어져 있는 것

"전략 1호"는 피보나치 그 자체가 아니라 **하나의 전략군 + 하나의 진입 방법**이다.

| 칸 | 지금 코드 | 이름 |
|---|---|---|
| 전략군 | — | **상승 사이클 눌림매매** |
| 모양 | `market_structure.py` · `zigzag.py` · `surge.py` | 오름 구간 이후 눌림 |
| 진입 | `fibonacci.py` · `entry_levels.py` · `fib_zone.py` | **피보나치 되돌림 진입 모델** |
| 청산 | `support_resistance.py` · `fills.py` · `stops.py` | 지지/저항 존 분할 매도 |
| 실행 | `strategy_one.py` · `walk_forward.py` | 백테스트 실행 하네스 |

**되돌림 비율 자체가 값을 한다고 가정하지 않는다.** 확인할 것은
"어떤 상황의 종목이 어떤 오름 뒤 어떤 눌림을 줄 때, 특정 되돌림 자리에서 사는 것이
이후 수익과 관계가 있는가"다.

같은 전략군에 형제 진입 방법을 나중에 끼워 넣을 수 있어야 한다
(전고점 지지 / 이동평균 / 거래대금 기반).

### 3.2 종목 선정은 진입·청산과 분리한다

같은 진입·청산 규칙을 두고 **종목 선정만 바꿔서** 성적을 견줄 수 있어야,
어떤 조건이 진짜 값을 하는지 구분된다. 그래서 종목 선정은 전략 코드 안에 박지 않고
**조건검색식(데이터)** 으로 정의한다 → [ADR-0009](../adr/0009-strategy-as-data.md)

### 3.3 4개 레이어와의 대응

```
src/layer1_data/       데이터 수집·정제·저장
src/layer2_llm_reading/ 글 해석 — LLM 이 들어가는 유일한 자리 (2단계~, 지금 비어 있음)
src/layer3_strategy/   종목 선정 · 모양 · 진입 · 청산 — 결정론적 규칙
src/layer4_execution/  백테스트 · 체결 · (향후) 실행
```

의존 방향은 한 방향: `layer4 → layer3 → layer2 → layer1`.
**LLM은 layer2 에서 멈춘다** — layer3(매매 결정)은 언제나 결정론적 코드다.

## §4. 확인 방법 (여기가 이 문서의 핵심이다)

### 4.1 그때 알 수 있었던 정보만 쓴다

모든 값은 이 질문을 통과해야 한다:

> **"이 값을 계산할 당시 실제로 알 수 있었는가?"**

| 항목 | ⭕ | ❌ |
|---|---|---|
| 가격 | 그날까지의 가격 | 다음 날 가격으로 오늘 신호 수정 |
| 시가총액 | 그날 시총 | 오늘 시총으로 과거 종목 선별 |
| 수급 | 그날 공개분 | 미래 수급을 누적해 "과거 강한 수급" 정의 |
| 뉴스·재료 | 그날까지 공개분 | 나중에 밝혀진 사실 반영 |
| 주도주 | 그날까지의 성과·거래대금·테마로 판단 | 몇 달 뒤 성과 보고 "그때 주도주였다" |
| 52주 신고가 | 그날까지의 52주 | 미래 신고가 알고 후보 지정 |
| 재무 | **접수일(rcept_dt) 이후**에만 | 대상 기간 기준으로 미리 사용 |

**오너 지적 (2026-08-07, 그대로 보존):** 오늘 기준으로 과거 종목을 늘어놓으면 이미 결과가
난 걸 보는 것이지 알아낸 게 아니다. 눌림 매매면 **"신고가를 찍은 그날까지의 데이터로
파동을 긋고, 그 다음날부터 어떻게 됐나"**를 봐야 한다. 실제로 그렇게 다시 재보니
좋은 종목과 나쁜 종목이 전혀 구분되지 않았다(무너진 쪽 반등이 오히려 더 컸다).

**코드로 강제한다.** "신호 계산 시점 < 체결 시점" 불변식을 테스트로 못 박는다.
지금 그렇게 돼 있다 — `wave_series` 는 "하루씩 굴린 값 == 그날까지 잘라 다시 계산한 값"이
같아야 통과하는 테스트가 붙어 있다(`tests/test_market_structure.py`).

### 4.2 당시 기준 종목 목록

각 시점에 **실제로 거래할 수 있었던 종목만** 본다.

- 2019년 데이터를 검사하면서 2026년 종목 목록을 쓰면 안 된다
- 2019년에 이미 상장폐지된 종목을 2026년 데이터에서 거꾸로 가져와도 안 된다
- **망한 회사를 데이터에 남긴다** — 빼면 수익률이 부풀려진다(살아남은 것만 보는 착시)

지금 상태: 수정주가 일봉 **5,478종목**에 상장폐지 종목이 들어 있다 ⭕

수급도 KIS 과거 조회로 전 종목을 백필했다. 2026-08-29 재실측에서 위 595종목 모두 자기
거래 기간 수급을 갖고, 일봉·수급 파일도 각각 5,478개다. 처음의 `0/595` 결손 경고는
해소됐다. 다만 분석마다 날짜 범위와 가격·거래대금을 표본 대조한다.

### 4.3 검사 구간

**오너 결정 (2026-08-16): 2007년부터, 나누지 않고 전체.**

- 코드가 구간을 강제하지 않는다. **화면에서 고른 날짜가 그대로 검사 구간**이다
- 기본값만 `2007-01-01 ~ 최신 거래일`
- 2007년으로 잡은 이유: 리먼 사태(2008-09-15) 전부터 보기 위해서
- 데이터는 **1995년부터** 있으므로 더 뒤로 갈 수도 있다

옛 3분할(연습/검증/시험)은 쓰지 않는다. 다만 그 원리는 알고 있어야 한다 —
**같은 구간을 보면서 값을 고치면, 그 구간 성적은 실력이 아니라 외운 결과에 가까워진다.**
최종 확인은 나무 모의투자(단계 5)가 대신한다.

### 4.4 변수 하나씩 → 조합

```
외국인 순매수 → 미래 수익
외국인 순매수 + 거래대금 증가 → 미래 수익
외국인 순매수 + 거래대금 증가 + 주도테마 → 미래 수익
외국인 순매수 + 주도테마 + 재료 + 눌림 → 미래 수익
```

이렇게 조건을 더할 때 **성적이 실제로 좋아지는지** 본다.

**단순히 합쳐서 좋아졌다고 채택하지 않는다.** 조건을 **하나씩 빼 보고**
그게 없을 때 얼마나 나빠지는지를 본다. 안 나빠지면 그 조건은 값을 못 하고 있는 것이다.

주도주처럼 뭉뚱그린 개념은 **구성 요소로 쪼개서 각각 먼저 확인한다** —
재료 / 차트 / 거래대금 / 프로그램 / 테마 대장 / 거래원 / 시황 / 투자심리.

### 4.5 무엇을 재나

단순 상관계수 하나만 보지 않는다. 가능하면 함께 본다:

```
미래 수익률 · 승률 · 평균 수익 · 평균 손실 · 기대값 · 손익비
최대 이익 폭(MFE) · 최대 손실 폭(MAE) · 수익률 분위수 · 최대 낙폭
거래 빈도 · 시장 국면별 성적 · 기간별 성적 · 안 본 구간 성적
```

**규칙:**

- 표본 **30건 미만**이면 통계를 믿지 않는다
- 승률과 순위 상관(IC)은 **다른 지표**다. 둘 다 본다
- 여러 조건을 동시에 시험하면 **우연히 통과하는 것이 늘어난다.** 보정을 한다
- **거래비용과 미끄러짐을 처음부터 넣는다.** 빼고 재면 다 좋아 보인다

### 4.6 실험 하나 = 산출물 한 벌

백테스트를 한 번 돌리면 나중에 그대로 되살릴 수 있게 남긴다:

```
설정(config) · 신호(signals) · 주문(orders) · 체결(fills)
거래(trades) · 자본곡선(equity) · 성적(metrics) · 비용(cost)
```

지금 상태: `runs` · `picks` · `notes` 까지 남는다. 체결 내역은 추가 예정.

**같은 입력 → 같은 출력.** LLM을 넣을 때는 미리 받아둔 자료(archive)로 되살릴 수 있게 한다.

### 5.2 소스 규칙

- **일봉 가격 정본 = 나무 수집본** (오너 결정 2026-08-16). 증권사가 보정한 수정주가라
  액면분할·병합이 이미 반영돼 있다. 실측: 우리 marcap 보정과 **250종목 중 18종목(7.6%)** 이
  어긋났고 전부 액면병합이었다(부산가스 10:1 병합이 7.5배 가짜 급등으로 찍혔다).
- **`marcap` = 상장폐지 종목 담당** + 날짜별 시가총액·상장주식수·종목명(패널이 쓴다).
  나무 마스터는 현재 상장분 4,298종목뿐이라 망한 회사가 없다. 상폐 종목엔 여전히 자체
  보정(ADR-0006)이 쓰인다. pykrx 는 KRX 로그인 게이트로 깨진 상태 — 신규 의존 ❌
- **수급 정본 = KIS.** 증분·교차검증 보조 = 나무 PLUG ([ADR-0012](../adr/0012-supply-demand-data-source.md))
- **주·월봉 정본 = 우리 일봉으로 만든 값** ([ADR-0021](../adr/0021-period-bars-from-daily.md)). 매 회차 전 종목을 일봉과 맞춰 보고
  어긋나면 덮는다. 나무·KIS 는 저장본이 없는 종목을 처음 받을 때만
- **주문 창구 = 나무증권(NH PLUG)** ([ADR-0018](../adr/0018-namuh-plug-broker.md)). KIS는 조회 전용 병행
- **수집 데이터는 재배포 금지** — GitHub 업로드 ❌, 로컬 `data/` 만

### 5.3 갱신은 "어디까지 받았나"를 적어 두고 그 뒤부터만 받는다

업계에서 쓰는 방식(high watermark)을 그대로 따른다: **마지막으로 받은 날을 작은 상태 파일
하나(`data/derived/_freshness.json`)에 적어 두고, 다음에 그 뒤부터만 받는다.** 이미 받은 것은
두 번 건드리지 않는다.

전에는 그걸 안 하고 데이터 파일을 전부 열어 마지막 날짜를 알아냈다. 실측 2026-08-16:

| 방식 | 파일 1개 | 일·주·월봉 증분(16,530개) |
|---|---|---|
| 파일 통째로 열기 | 15.3ms | **4.2분** — 받을 게 하나도 없는데도 |
| 날짜 열만 읽기 | 1.6ms | 0.5분 |
| 워터마크 파일 1개 | — | **1밀리초** |

**켤 때 자동으로 하는 것은 빠른 것뿐이다.** 차트 일봉 정본(`data/marcap`)은 깃 저장소
복제본이라 `git pull` 몇 초면 최신이 된다 — 백엔드를 켜면 뒤에서 그것만 한다. 종목마다
따로 받아야 하는 수급·신용잔고는 호출 한도를 크게 태우므로 **서버가 멋대로 시작하지 않는다.**
그건 사람이 `scripts/update_data.py` 로 돌린다.

**화면은 며칠이 아니라 등급을 보여준다.** 묵은 데이터는 화면이 멀쩡히 그려져서 눈에 안 띈다 —
차트도 나오고 숫자도 그럴듯하다. 그래서 날짜 옆에 색을 준다(괜찮음·조금 밀림·묵음).
셀 때는 **장이 열린 날로** 센다 — 달력으로 세면 월요일 아침마다 헛경고가 뜬다.

### 5.4 분봉은 주기마다 따로 받는다 — 합성하지 않는다

굵은 봉을 가는 봉에서 다시 만들지 **않는다.** 각 주기를 증권사에서 따로 받아 그대로 둔다.

**근거 (실측 2026-08-16).** 삼성전자 60분봉을 120분봉으로 합쳐 실제 120분봉과 견줘 봤다.
봉 경계는 정확히 맞는데(하루 7봉 → 4봉) **값이 다 맞지는 않았다**:

| 항목 | 일치 |
|---|---|
| 종가 | 5,965 / 5,965 (100%) |
| 고가 | 5,964 / 5,965 |
| 시가·저가 | 5,958 / 5,965 (99.88%) |
| 거래량 | 5,961 / 5,965 |

**왜 어긋나나.** 주기마다 따로 받은 자료라 한쪽에 문제가 있으면 그 문제가 옮겨 붙는다.
실제 예 — 2021-12-29 삼성전자 60분봉은 10:00~14:00 다섯 봉이 전부 80,300 으로 같다(자료 이상).
이걸로 120분봉을 만들면 고가가 **80,300** 이 되는데, 증권사가 준 120분봉은 **79,000** 이다.
**합성하면 멀쩡한 자료를 이상한 자료로 덮어쓰게 된다.**

그리고 증권사가 준 봉이 곧 **그때 화면에서 보이던 값**이다. 계산으로 만든 값이 아니다.

## §6. 실행

### 6.1 신호와 체결을 분리한다

```
신호 → 체결 시점 → 가격 → 미끄러짐 → 수수료 → 유동성 → 실제 체결
```

신호가 났다고 **항상 전량 체결됐다고 가정하지 않는다.** 가능하면 기록한다:
주문 수량 · 실제 체결 수량 · 미체결 · 주문 거부 · 현금 부족 · 유동성 부족.

### 6.2 지금 체결 가정과 그 한계

- 계획은 기준일까지의 데이터로 세우고, 체결은 **그 다음 날부터** 본다
- 매수 = 저가 ≤ 목표가 / 매도 = 고가 ≥ 목표가
- **⚠️ 닿기만 해도 체결로 친다.** 실제로는 앞 물량에 막혀 못 살 수 있다.
  지정가라 미끄러짐은 안 물린다 — 대신 **얼마나 아슬아슬했는지를 기록**해서,
  호가를 몇 개 더 줘야 하는지 오너가 값을 바꿔가며 확인한다
- 계산상 가격과 **실제 낼 수 있는 가격을 분리**한다. 반올림은 **불리한 쪽**으로 —
  유리한 쪽으로 하면 백테스트에서만 체결되는 거래가 생긴다

### 6.3 거래비용

| 수준 | 값 | 뜻 |
|---|---|---|
| 0 | 0% | **쓰면 안 됨** |
| 1 | 0.3% | 수수료만 — 최소 기준선 |
| 2 | **0.5%** | 수수료 + 미끄러짐 + 호가 영향 — **기본값** |
| 3 | 0.8%+ | 변동성 클 때 — 최악 가정 시험 |

→ [ADR-0004](../adr/0004-transaction-costs.md)

### 6.4 실거래로 가는 길

```
백테스트 통과 → 전략 후보 → 오늘 시장 신호 → 사용자 승인 → 주문 실행
```

**백테스트가 좋다는 이유만으로 자동 주문하지 않는다.** 네 단계가 분리돼 있어야 한다.

- 단계 6 전까지 실계좌 자금 이동 ❌
- 실계좌 주문은 사람이 스크립트로만 (`namuh_buy_one.py`)
- 단계 5는 나무 모의투자 (moapi, 계좌구분 03)

## §8. 운영

### 8.1 하루

```
새벽    시황·관심 종목 훑기 (지금은 사람이, 나중엔 시스템이 후보를 뽑아줌)
장 전   오늘 진입 검토할 종목 확정 → 사용자 승인 → 예약 주문 전송
장중    무개입 (의도적)
저녁    회고 + 내일 미리보기
주말    큰 사건 없으면 안 함
```

**장중 무개입 이유:** 개입이 통계적으로 손해이기 때문이다 (§1.4 Barber & Odean).
"이번엔 다르다"는 직관 개입 ❌.

**개입해야 할 때가 있다면 보수 방향만** — 줄이기·청산·중단은 되고,
추가 매수·손절 풀기는 안 된다.

### 8.2 지켜보기

- 전략별 실제 성과를 계속 기록한다
- 성적이 백테스트 기대치에서 벗어나면 신호로 본다
- 힘이 약해지거나 사라지면 **"새 가설을 연구할 때"라고 알린다**

이게 이 시스템에서 말하는 "진화"다. AI가 새 전략을 발명하는 게 아니다.

**알파는 원래 닳는다** — McLean & Pontiff(2016) 발표 후 평균 −58%,
Chen & Velikov(2022) 거래비용 후 −93%. 부패를 전제로 설계한다.

## §9. AI를 어디까지 쓰나

### 9.1 지금 (1단계)

**정량만.** LLM은 매매 경로에 없다.
AI(클로드)의 일은 코딩과 "시키면 계산 돌리기"다 (§0.4).

### 9.2 2단계에 들어갈 때

- LLM은 **layer2 까지만.** 매매 결정(layer3)은 언제나 결정론적 코드
- LLM 출력은 **등급(ordinal)까지만.** 확률·목표가 ❌
- LLM에게 넘길 때 **종목명·날짜·특징적 수치를 가린다** —
  안 가리면 LLM이 이미 아는 결과를 근거로 답한다
- **1단계(정량만) 성적과 2단계(+LLM) 성적을 따로 재서 견준다.**
  LLM을 넣어 실제로 나아졌는지 숫자로 보여야 한다
- **LLM 쓴 돈도 비용으로 적는다**

### 9.3 MCP 사용 규칙 (타협 불가)

MCP는 개발 보조로만 쓴다. **매매 실행 경로(주문·포지션·자금 이동)에 절대 넣지 않는다.**

- 허용: API 문서 검색, 코드 생성 보조, 이슈 관리, 데이터 탐색
- 금지: LLM/MCP가 BUY/SELL·포지션 크기·손절선을 정하거나 주문을 전송하는 것
- 공식 KIS·나무 MCP는 **조회 전용**으로만 (주문 도구는 권한 거부 목록에 등록)

자세한 것은 `CLAUDE.md`.

## §10. 하지 말 것

### 10.1 확인 방법

- ❌ 같은 구간을 보면서 값을 고치고 그 구간 성적을 실력으로 읽기
- ❌ 백테스트 통과 즉시 풀시드 투입
- ❌ 거래비용·미끄러짐 무시한 백테스트 신뢰
- ❌ 표본이 적은 통계로 조건 채택
- ❌ 조건을 강화했는데 지표가 안 올랐는데도 채택
- ❌ 단순히 합쳐서 좋아졌다고 채택 (하나씩 빼 보기 안 함)
- ❌ 여러 조건을 동시에 시험하면서 보정 안 하기
- ❌ 흔들리는 기준으로 통계내기 (기준 사건을 못 박고 시작)
- ❌ 각 층을 따로 안 재고 성적을 더해서 추론하기 ("3% + 4% = 7%")

### 10.2 미래 정보

- ❌ 오늘 시총·오늘 테마 분류로 과거 종목 고르기
- ❌ 미래 수급을 누적해 "과거에 강했던 종목" 정의
- ❌ 나중에 밝혀진 사실을 과거 재료에 반영
- ❌ 미래 신고가를 알고 과거 시점의 후보 지정
- ❌ 종목명·날짜를 그대로 노출한 채 LLM 백테스트

### 10.3 매매

- ❌ 미수·신용·스탁론
- ❌ 킬스위치 우회 / 무시
- ❌ "이번엔 다르다" 직관 개입
- ❌ 단일 알파 100% 의존
- ❌ 시장 충격 큰 종목에 시장가 진입
- ❌ 단타 (스윙만 — 오너 결정)
- ❌ LLM 좋다고 한 종목을 확인 없이 매수
- ❌ AI에게 룰 자동 변경 권한 주기

### 10.4 역할

- ❌ AI가 조건·임계값·우선순위·검사 구간을 정하기
- ❌ AI가 확인 실험 목록을 설계하기
- ❌ 화면에서 고를 수 있는 것을 파이썬에 다시 정의하기 (경로가 둘로 갈린다)

### 10.5 늘 의심할 것

- *"내 전략은 무엇 때문에 작동하지 않을까?"*
- *"이 성적은 실력인가, 그 구간을 외운 것인가?"*
- *"이 값을 계산할 당시 정말 알 수 있었나?"*
- *"기한 압박 때문에 확인을 건너뛰고 있지 않나?"*
- *"화면에서 고를 수 있는 걸 내가 코드에 박고 있지 않나?"*

## §12. 미룬 것

여기는 **오너 결정을 기다리는 목록이 아니다.** 조건·임계값·진입 방식·검사 구간은
오너가 화면에서 정한다(§0.4) — 그건 "미결"이 아니라 그냥 오너 몫이다.

여기 적는 것은 **아직 안 만든 기능**뿐이다. 만드는 건 AI 일이므로 남겨 둔다.

| 안 만든 것 | 그래서 지금 어떻게 되나 | 추적 |
|---|---|---|
| 포트폴리오 자본 배분 | 백테스트가 "돈 무한" 전제라 **계좌 수익률이 아니다.** 승률·종목당 수익률만 본다 | BORB-66 |
| 시장 상황 판정 조건 | 화면에 오름장/내림장 조건이 없다 | — |
| 수급 조건 | 수급 데이터는 있는데 화면에서 고를 조건이 없다 | — |
| 데이터 창구 호출부 이전 | 창구는 만들었으나 기존 코드는 아직 옛 경로를 쓴다 | — |

데이터에 뭐가 없는지는 **§5.4 알려진 구멍**에 있다. 여기 중복해 적지 않는다.
